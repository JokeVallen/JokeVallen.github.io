一、客观题

C# 与运行时

1. 在 Unity 中使用 async void 的主要风险是？
A. 一定无法编译　B. 异常无法被外层 try/catch 捕获　C. 只能用于 UI 事件　D. 不支持 await

  • 正确答案：B
  • 解析：async void 没有可等待的 Task，异常会直接抛到 SynchronizationContext，调用方无法用普通 try/catch 捕获。Unity 中应优先使用 async UniTaskVoid 或 async Task。

2. 关于 Span<T>，下列说法正确的是？
A. 可以存入 List<Span<int>>　B. 可以跨 await 保存　C. 是 ref struct，不能装箱、不能作为类字段　D. 只能用于只读字符串

  • 正确答案：C
  • 解析：Span<T> 是 ref struct，只能存在于栈上，不能装箱、不能作为类字段、不能跨 await 保留。

3. 把一个可变对象作为 Dictionary 的 key 后修改了参与 GetHashCode 的字段，最可能发生什么？
A. 通常再也找不到该项　B. Dictionary 自动重新哈希　C. 一定立即抛异常　D. Dictionary 自动重新排序

  • 正确答案：A
  • 解析：Dictionary 用哈希值定位桶。key 的哈希变化后，查找会去错误的桶，导致找不到原项。key 应使用不可变对象或稳定哈希。

4. 关于 GC.Collect，正确的做法是？
A. 每帧调用　B. 只回收非托管内存　C. 会立刻释放所有引用对象　D. 强制回收可能造成卡顿，不应滥用

  • 正确答案：D
  • 解析：GC.Collect 触发完整回收，可能造成明显卡顿，且不会释放仍有引用的对象。应通过减少分配和对象池解决问题。

5. 关于 ValueTask，下列说法正确的是？
A. 可以任意多次 await　B. 一般只能消费一次，重复 await 可能异常　C. 不能返回结果　D. 一定比 Task 慢

  • 正确答案：B
  • 解析：ValueTask 是为减少分配设计的，通常只能 await 一次；多次 await 或保存后重复消费可能触发未定义行为。

6. 将 Expression<Func<int>> 编译成委托后反复调用，与每次 MethodInfo.Invoke 相比通常？
A. 编译后的委托调用更快　B. 一定更慢　C. 不支持参数　D. 不再依赖反射

  • 正确答案：A
  • 解析：表达式树编译后生成委托，后续调用避免每次反射参数打包与安全检查，通常更快；但编译本身有成本，应缓存。

7. WeakReference<T> 的主要用途是？
A. 阻止对象被 GC 回收　B. 提供线程安全集合　C. 允许对象被回收并可检查是否存活　D. 存储值类型

  • 正确答案：C
  • 解析：弱引用不阻止 GC 回收目标对象，适合缓存、监听器表等场景；使用前需检查 TryGetTarget。

8. Interlocked.Increment 的作用是？
A. 加线程锁　B. 原子自增　C. 序列化对象　D. 反射调用

  • 正确答案：B
  • 解析：Interlocked 提供原子操作，适合无锁计数；它不能替代复杂临界区的锁。

9. 一个类型实现了 IAsyncDisposable，正确释放方式是？
A. 只能调用 Dispose　B. 必须阻塞等待　C. 不支持异步　D. 使用 await using

  • 正确答案：D
  • 解析：await using 会调用 DisposeAsync，适合异步释放资源；同步 using 只适用于 IDisposable。

10. string.Intern 的作用是？
A. 把字符串放入驻留池　B. 压缩字符串内容　C. 深拷贝字符串　D. 线程安全拼接

  • 正确答案：A
  • 解析：Intern 返回驻留池中的字符串引用，适合少量高频固定字符串；滥用会增加驻留池压力且字符串永不回收。

Unity 引擎

11. Awake 与 OnEnable 的通常执行顺序是？
A. 随机　B. OnEnable 先于 Awake　C. Awake 先于 OnEnable　D. 只在 Start 之后

  • 正确答案：C
  • 解析：对象激活时先调用 Awake，再调用 OnEnable；Start 在第一次 Update 前执行。

12. FixedUpdate 的调用特点是？
A. 每帧调用一次　B. 按固定时间步长调用，适合物理　C. 只在移动端调用　D. 专门用于 UI

  • 正确答案：B
  • 解析：FixedUpdate 按 fixedDeltaTime 调用，物理计算应放在这里；渲染帧更新用 Update。

13. DontDestroyOnLoad 的作用是？
A. 切换场景时保留对象　B. 立即销毁对象　C. 只保留一帧　D. 只对 UI 有效

  • 正确答案：A
  • 解析：该对象在场景切换时不会被销毁，常用于管理器、音频源等；需要自己处理重复实例和生命周期。

14. 运行时直接修改 ScriptableObject 资产可能带来什么问题？
A. 每次运行自动重置　B. 不能存数据　C. 只能存字符串　D. 在 Editor 中可能污染资产，需要运行时副本

  • 正确答案：D
  • 解析：ScriptableObject 是资产，运行时修改可能写回 Editor 中的资产。需要只读配置时可在运行时 Instantiate 一份副本。

15. 使用 Additive 加载场景后，SetActiveScene 主要影响什么？
A. 自动卸载旧场景　B. 新实例化对象归属和光照设置　C. 不能同时加载多个场景　D. 只影响 UI

  • 正确答案：B
  • 解析：活动场景决定新对象默认属于哪个场景，也影响光照与天空盒等设置；不会自动卸载其他场景。

16. Physics.OverlapSphereNonAlloc 相比 OverlapSphere 的优势是？
A. 避免每次调用分配数组　B. 一定更快　C. 只能用于 2D　D. 不能指定 LayerMask

  • 正确答案：A
  • 解析：NonAlloc 版本复用调用方传入的数组，减少 GC；结果数量以返回值表示，数组可能保留旧数据。

17. Animator 的 Culling Mode 设置为 Cull Completely 时？
A. 不可见时仍每帧更新　B. 只剔除阴影　C. 不可见时完全停止更新　D. 只对 UI 有效

  • 正确答案：C
  • 解析：Cull Completely 会在不可见时完全停止动画更新，适合远处角色；但重新可见时需要正确恢复状态。

18. SceneManager.LoadSceneAsync 设置 allowSceneActivation = false 后？
A. 立即激活场景　B. 无法加载　C. 只加载 UI　D. 加载到约 0.9 后等待激活

  • 正确答案：D
  • 解析：异步加载进度到约 0.9 后会停住，等待 allowSceneActivation = true；常用于加载界面与进度条。

UI / UGUI

19. 关于 Canvas 重建，下列说法正确的是？
A. 一个 Canvas 下图形变化可能触发批次重建　B. 只重建单个 Image　C. 不影响性能　D. 只影响布局

  • 正确答案：A
  • 解析：Canvas 负责管理批次，子元素脏标记会触发 Canvas 批次重建；把动态 UI 拆到独立 Canvas 可缩小影响范围。

20. 大量静态 UI 与频繁变化的动态 UI 应如何组织？
A. 放在同一个 Canvas　B. 拆分到不同 Canvas　C. 增加更多 Mask　D. 每帧 SetActive

  • 正确答案：B
  • 解析：独立 Canvas 可以把重建范围限制在动态部分，避免静态 UI 被反复重建。

21. RectMask2D 与 Mask 的性能关系通常是？
A. Mask 更轻　B. 完全一样　C. RectMask2D 支持异形裁剪　D. RectMask2D 通常更轻，只支持矩形

  • 正确答案：D
  • 解析：RectMask2D 不依赖 Stencil，通常更轻；Mask 支持 Sprite Alpha 异形裁剪，但会增加渲染状态切换。

22. ContentSizeFitter 与 LayoutGroup 互相依赖时最可能出现？
A. 自动优化　B. 性能提升　C. 反复布局重建　D. 只影响文本

  • 正确答案：C
  • 解析：父物体根据子物体尺寸撑开，子物体又依赖父物体排列，容易形成多轮 Layout Rebuild，甚至抖动。

23. 数据量很大的 ScrollRect 列表应优先采用？
A. 虚拟滚动与对象池　B. 一次性实例化全部 Item　C. 每帧重建布局　D. 禁用 Mask

  • 正确答案：A
  • 解析：虚拟滚动只创建可视区域附近的单元格，滚动时复用，避免大量 GameObject 与布局计算。

24. TMP 动态字体图集扩容时可能带来？
A. 无成本　B. CPU 峰值和图集重建　C. 只在 Editor 发生　D. 只影响音频

  • 正确答案：B
  • 解析：新增字形会触发图集纹理扩容与重建，可能造成尖峰。应预生成常用字符集并配置 Fallback。

25. CanvasScaler 的 Scale With Screen Size 模式主要用于？
A. 固定物理尺寸　B. 完全不缩放　C. 只处理刘海屏　D. 按参考分辨率缩放 UI

  • 正确答案：D
  • 解析：该模式根据参考分辨率和 Match 参数缩放 Canvas，适合多数移动端 UI；刘海屏仍需 SafeArea。

26. 优化 GraphicRaycaster 的常见做法是？
A. 所有元素开启 raycastTarget　B. 增加更多 Canvas　C. 关闭装饰元素的 raycastTarget　D. 每帧重建布局

  • 正确答案：C
  • 解析：只有真正需要响应点击的 UI 才开启 raycastTarget，可显著减少射线检测与排序开销。

27. CanvasGroup.blocksRaycasts = false 的效果是？
A. 组内元素不接收射线　B. 视觉上隐藏　C. 禁用动画　D. 销毁对象

  • 正确答案：A
  • 解析：它只控制射线检测，不改变显示；隐藏需要改 alpha 或 SetActive。

28. EventSystem 当前选中对象丢失时，较合理的处理是？
A. 重启场景　B. 检查并重新 SetSelectedGameObject　C. 清空 Canvas　D. 关闭 Raycaster

  • 正确答案：B
  • 解析：选中对象可能因销毁或失活丢失，应在界面切换后显式设置默认选中项，保证手柄/键盘导航。

资源与热更

29. Addressables 释放资源句柄应使用？
A. Destroy(handle)　B. 只调用 Resources.UnloadUnusedAssets　C. Addressables.Release(handle)　D. GC.Collect

  • 正确答案：C
  • 解析：Addressables.Release 减少引用计数；计数归零后资源才可能卸载。

30. 通过 Addressables.InstantiateAsync 创建的实例应如何释放？
A. Addressables.ReleaseInstance(go)　B. 只 Destroy(go)　C. 只 Release(handle) 就足够　D. 不需要释放

  • 正确答案：A
  • 解析：实例需要 ReleaseInstance 才能正确归还实例与引用计数；只 Destroy 可能造成计数残留。

31. AssetBundle 调用 Unload(true) 的风险是？
A. 一定安全　B. 只卸载依赖　C. 不释放内存　D. 可能卸载正在使用的资源

  • 正确答案：D
  • 解析：Unload(true) 会销毁已从该包加载的 Asset 对象，若仍被场景引用会变成 Missing。

32. Sprite 被重复打包进多个 AssetBundle 的常见原因是？
A. 图集太大　B. 精灵同时被单独引用又被图集包含　C. 没有 Mipmap　D. 使用 ASTC

  • 正确答案：B
  • 解析：资源同时被单独引用和图集包含时，打包器可能在不同包中各打一份，造成冗余。

33. 纹理开启 Read/Write 的主要影响是？
A. 减少内存　B. 提升压缩率　C. 增加一份 CPU 内存副本　D. 只影响 UI

  • 正确答案：C
  • 解析：Read/Write 允许 CPU 访问纹理，但会保留额外内存副本；不需要时关闭。

34. 短促、高频的 UI 音效最适合的 Load Type 是？
A. Decompress On Load　B. Streaming　C. Compressed In Memory　D. 三者无差别

  • 正确答案：A
  • 解析：短音效解压后常驻内存，播放时 CPU 开销低；长音乐才用 Streaming。

35. HybridCLR 主要解决什么问题？
A. 资源压缩　B. UI 合批　C. 网络同步　D. C# 热更与 AOT 泛型

  • 正确答案：D
  • 解析：HybridCLR 通过 AOT + 解释器混合方案支持 C# 热更，补足纯 AOT 下泛型与动态代码限制。

36. 排查资源泄漏时，首要查看的是？
A. 显卡型号　B. 引用链　C. 屏幕分辨率　D. 当前帧率

  • 正确答案：B
  • 解析：资源无法释放通常是因为仍有静态字段、事件、协程或句柄持有引用。

性能优化

37. DrawCall 与 SetPass 的关系是？
A. 一个 SetPass 可能对应多个 DrawCall，状态切换是主要开销　B. 两者完全相等　C. SetPass 越多越好　D. 只和 UI 有关

  • 正确答案：A
  • 解析：SetPass 表示切换渲染状态，多个 DrawCall 可能共享一个 SetPass；优化目标是减少状态切换与 DrawCall。

38. 静态合批的限制是？
A. 任意物体都能合　B. 只对 UI 有效　C. 物体不能移动，并受材质、顶点数、平台限制　D. 不需要相同材质

  • 正确答案：C
  • 解析：静态合批把静态网格合并成大网格，移动物体不适用，并有顶点上限和材质要求。

39. Overdraw 指的是？
A. 顶点过多　B. 同一像素被多次绘制　C. 内存不足　D. 网络延迟

  • 正确答案：B
  • 解析：半透明 UI、粒子、重叠模型都会造成 Overdraw，移动端 GPU 填充率容易成为瓶颈。

40. 以下哪些是 Unity 中常见的 GC 分配来源？
A. 仅 new GameObject　B. 仅 Resources.Load　C. 仅网络消息　D. string 拼接、LINQ、闭包、装箱

  • 正确答案：D
  • 解析：字符串、LINQ、闭包、装箱、协程迭代器、params 数组等都可能产生托管堆分配。

41. Memory Profiler 主要用于？
A. 分析内存快照与引用链　B. 分析帧率　C. 分析网络包　D. 编译 Shader

  • 正确答案：A
  • 解析：Memory Profiler 可抓取快照、对比差异并查看对象引用关系，是定位泄漏的核心工具。

42. Frame Debugger 主要用于？
A. 查看 C# 调用栈　B. 查看网络包　C. 查看每个 DrawCall/Batch　D. 查看 GC

  • 正确答案：C
  • 解析：Frame Debugger 可逐 DrawCall 查看渲染过程、批次被打断的位置和渲染状态。

43. 启动优化的合理方向是？
A. 每帧调用 GC　B. 延迟加载、资源拆包、异步初始化　C. 增加粒子特效　D. 全部改用 Resources

  • 正确答案：B
  • 解析：启动阶段应减少首屏依赖、并行异步加载、把非必要系统延后初始化。

44. 为什么必须做真机 Profiling？
A. 不需要　B. Editor 与真机完全一致　C. 只用于 UI　D. 真机性能、发热和降频与 Editor 差异很大

  • 正确答案：D
  • 解析：Editor 不能代表移动端 CPU/GPU、内存带宽和热降频表现，性能问题必须在目标机型验证。

渲染

45. URP 中 SRP Batcher 主要减少？
A. 纹理内存　B. 顶点数量　C. 材质相关的 CPU 设置开销　D. 网络延迟

  • 正确答案：C
  • 解析：SRP Batcher 通过持久化材质属性减少每 DrawCall 的 CPU 设置成本，但要求 Shader 兼容。

46. GPU Instancing 的典型要求是？
A. 相同 Mesh/Material，通过实例化数据批量绘制　B. 任意不同 Mesh 都可合　C. 只支持 UI　D. 不需要 Shader 支持

  • 正确答案：A
  • 解析：Instancing 适合大量相同网格与材质，通过每实例属性批量提交，减少 DrawCall。

47. MaterialPropertyBlock 的作用是？
A. 压缩纹理　B. 生成图集　C. 网络同步　D. 每实例覆盖材质属性而不复制材质

  • 正确答案：D
  • 解析：MaterialPropertyBlock 可给单个 Renderer 设置属性，避免为每个实例创建材质副本，但可能影响 SRP Batcher。

48. Shader Variants 过多会带来？
A. 减少包体　B. 增加构建时间、包体和加载开销　C. 提升帧率　D. 没有影响

  • 正确答案：B
  • 解析：变体数量膨胀会增加构建时间、包体和运行时加载成本，应通过关键字裁剪和 Stripping 控制。

49. 透明物体的常见渲染顺序是？
A. 从近到远　B. 随机　C. 通常从远到近，并依赖排序　D. 与相机无关

  • 正确答案：C
  • 解析：透明物体通常按相机距离从远到近绘制，依赖排序保证混合结果；排序错误会出现穿插。

50. ASTC 主要用于？
A. 移动端纹理压缩　B. 音频压缩　C. 网络协议　D. UI 布局

  • 正确答案：A
  • 解析：ASTC 是移动端常用纹理压缩格式，可在质量与体积之间按块大小取舍。

网络

51. TCP 粘包的常见处理方式是？
A. 增加睡眠　B. 关闭 Nagle　C. 改用 UDP 一定解决　D. 长度前缀、分隔符或固定长度

  • 正确答案：D
  • 解析：TCP 是字节流，必须由应用层定义消息边界；长度前缀是最常用方案。

52. 帧同步与状态同步的主要区别是？
A. 完全一样　B. 帧同步传输入，状态同步传状态　C. 帧同步适合所有游戏　D. 状态同步不需要服务器

  • 正确答案：B
  • 解析：帧同步同步玩家输入并由客户端确定性演算；状态同步由服务器下发权威状态。

53. 网络心跳的主要作用是？
A. 检测连接存活与 NAT 超时　B. 压缩资源　C. 提升帧率　D. 加密协议

  • 正确答案：A
  • 解析：心跳保持连接活跃，及时发现断线，并防止 NAT 映射超时。

54. Protobuf 的主要优势是？
A. 人类可读　B. 不需要 schema　C. 体积小、序列化快、跨语言　D. 只能用于 C#

  • 正确答案：C
  • 解析：Protobuf 使用二进制编码和 schema，体积小、跨语言，适合网络协议；可读性不如 JSON。

55. 断线重连设计的关键是？
A. 直接重启客户端　B. 清空存档　C. 关闭心跳　D. 会话恢复、状态同步、幂等重发

  • 正确答案：D
  • 解析：重连需要恢复会话、补齐状态，并保证重复请求不会造成副作用。

架构与工程

56. 事件总线最常见的问题是？
A. 订阅未退订导致泄漏或重复回调　B. 线程安全　C. 不能传参　D. 只能用于 UI

  • 正确答案：A
  • 解析：订阅者销毁后未反注册，事件中心仍持有引用，造成泄漏和空回调；应统一生命周期管理。

57. 对象池设计的关键是？
A. 无限增长　B. 重置对象状态并设置容量上限　C. 每次重新 new　D. 只用于 UI

  • 正确答案：B
  • 解析：对象复用时必须重置状态、取消订阅、清理计时器，并设置上限避免内存无限增长。

58. UI 框架分层的合理做法是？
A. 所有逻辑写在按钮回调里　B. 每个 UI 都做成单例　C. 视图、逻辑、数据分离，统一弹窗与生命周期　D. 完全不做管理

  • 正确答案：C
  • 解析：分层能降低耦合，统一管理打开、关闭、缓存、遮罩和异步加载。

59. 热更新版本管理的关键是？
A. 只更新客户端　B. 不需要 CDN　C. 不需要校验　D. 资源与代码版本一致且可回滚

  • 正确答案：D
  • 解析：热更必须保证程序集、资源、配置版本匹配，并提供下载校验、灰度与回滚能力。

60. 技术方案评审最应关注？
A. 性能、维护性、风险与回滚　B. 只选最新技术　C. 代码行数　D. 个人偏好

  • 正确答案：A
  • 解析：高级工程师的方案评审要综合性能、可维护性、上线风险和失败回滚，而不是追求技术新颖。

二、主观题

1. 设计一个支持异步加载、缓存、防重复打开和生命周期管理的 UI 框架。

  • 参考点：UIManager 分层、打开/关闭栈、异步加载句柄、缓存策略、遮罩与层级、OnOpen/OnClose、防重复请求、返回键、异常回滚。

2. Addressables 资源泄漏如何定位和治理？

  • 参考点：Memory Profiler 快照对比、引用链、句柄计数、Release/ReleaseInstance、共享资源修改、场景切换清理、定期资源审计。

3. 如何设计大列表虚拟滚动？

  • 参考点：可视区间计算、对象池、前缀和/二分定位、可变高度、回收重置、滚动事件节流、RectMask2D、避免 LayoutGroup 全量重建。

4. 真机掉帧如何系统排查？

  • 参考点：先确认 CPU/GPU/内存/发热，Profiler 分线程、Frame Debugger 看 DrawCall、Memory Profiler 看 GC、对比机型与场景、定位热点后做 AB 测试。

5. TMP 中文动态字体如何优化？

  • 参考点：预生成常用字符集、Fallback、字体图集尺寸、动态图集扩容、低分配 SetText、避免每帧改文本、按语言拆分字体资产。

6. 设计一个健壮的事件总线。

  • 参考点：泛型事件、订阅/退订、弱引用或生命周期绑定、重复订阅、异常隔离、线程安全、调试面板、事件命名规范。

7. 如何做热更新版本管理与回滚？

  • 参考点：版本清单、资源与代码一致性、CDN、增量下载、校验、灰度、回滚策略、失败降级、本地缓存。

8. 如何设计可维护的 UI 红点系统？

  • 参考点：树形依赖、事件驱动、叶子节点计数、路径注册、批量刷新、避免每帧遍历、与配置表解耦。

9. 线上 UI 点击穿透如何排查？

  • 参考点：EventSystem 当前射线结果、raycastTarget、CanvasGroup、遮罩层级、Sorting Order、GraphicRaycaster、点击日志、最小复现。

10. 如何做包体优化和资源分包？

  • 参考点：资源审计、纹理/音频压缩、图集、重复资源、首包最小化、按场景/模块分包、远程资源、构建报告、版本增量。

11. 设计一个跨平台 SDK 接入方案。

  • 参考点：统一接口层、平台实现分离、Android JNI/iOS OC 桥接、回调线程、生命周期、权限、异常降级、Editor Mock。

12. 如何制定团队 UI 性能规范？

  • 参考点：Canvas 拆分、图集规范、raycastTarget 规范、TMP 字符集、布局重建限制、列表虚拟化、Overdraw 预算、真机验收指标、CI 检查。
