一、客观题

C# 基础

1. 阅读以下代码，输出顺序是？

A. x → B → A　B. A → x → B　C. A → B → x　D. x → A → B

  • 正确答案：D
  • 解析：派生类实例字段初始化器先执行，随后进入基类构造函数，最后执行派生类构造函数体。因此顺序为 x → A → B。这是继承体系中容易记反的边界。

2. 某类型只重写了 == 运算符（按 Id 比较），没有重写 Equals 和 GetHashCode。把它作为 HashSet<T> 的元素时，最可能的现象是？
A. 可能把相同 Id 的对象当成不同元素　B. 一定会编译报错　C. 能按 Id 正确去重，因为 HashSet 内部调用 ==　D. 运行时必定抛出 InvalidOperationException

  • 正确答案：A
  • 解析：HashSet/Dictionary 通过 GetHashCode 定位、用 Equals 判等，与 == 是两套机制。重写 == 时应同步重写 Equals 与 GetHashCode，否则集合语义与运算符语义不一致。

3. 以下代码编译通过，运行结果是？

A. 正常运行，arr[0] 为 1　B. 编译期报错，不能把 string[] 赋给 object[]　C. 运行时把 1 自动转成字符串　D. 运行时抛出 ArrayTypeMismatchException

  • 正确答案：D
  • 解析：数组协变允许 string[] 赋给 object[]，但运行时数组仍记录元素类型为 string；写入 int 会触发 ArrayTypeMismatchException。协变只在读取时安全。

4. 下列泛型赋值不合法的是？
A. IEnumerable<object> e = new List<string>();　B. Func<string, object> f = s => s;　C. IEnumerable<string> e = new List<object>();　D. Action<string> a = (Action<object>)(o => { });

  • 正确答案：C
  • 解析：IEnumerable<out T> 支持协变，因此 List<string> 可以赋给 IEnumerable<object>，反之则不行。Action<in T> 支持逆变，Func 的输出支持协变，对应赋值合法。因此不合法的是把 IEnumerable<object> 赋给 IEnumerable<string>。

5. 有以下两个重载，执行 dynamic d = “hi”; F(d); 的结果是？

A. 编译期报错，无法确定重载　B. 运行时绑定，输出 string　C. 输出 object　D. 随机选择其中一个

  • 正确答案：B
  • 解析：dynamic 会跳过编译期重载解析，在运行时根据实际类型选择重载，因此调用 F(string)。若直接写 F(“hi”) 则在编译期绑定。

6. 在 Unity 中，下面的异步方法最可能在非主线程访问 Unity API、从而出问题的是？
A. await Task.Delay(100).ConfigureAwait(false); transform.position = Vector3.zero;　B. await UniTask.Delay(100); transform.position = Vector3.zero;　C. await Task.Run(() => { }); transform.position = Vector3.zero;　D. await Task.Delay(100); transform.position = Vector3.zero;

  • 正确答案：A
  • 解析：Unity 的同步上下文会把普通 await 的后续逻辑调回主线程；ConfigureAwait(false) 放弃该上下文，后续可能在线程池线程执行，此时访问 Transform 等 Unity API 不再安全。

7. 使用 foreach 遍历一个由 yield 实现的迭代器时，在循环中提前 break，迭代器中的 finally 块会怎样？
A. 取决于迭代器是否为 async，普通迭代器不执行　B. 只有发生异常时才会执行，正常 break 不执行　C. 不会执行，迭代器被直接丢弃，finally 被跳过　D. 会执行，foreach 结束时会调用 Dispose

  • 正确答案：D
  • 解析：foreach 生成的 try/finally 会在退出循环时调用枚举器的 Dispose；编译器生成的迭代器状态机在 Dispose 中执行 finally，用于释放资源。

8. 泛型方法带约束 where T : struct 时，方法内 T? 的含义是？
A. 与 T 完全相同　B. 编译错误，值类型不能写成 T?　C. Nullable<T>　D. 仅当 T 为引用类型时才合法

  • 正确答案：C
  • 解析：where T : struct 表示非可空值类型，但 T? 会被解释为 Nullable<T>，用于表达可空值类型；Nullable<T> 本身不满足 struct 约束，但 T? 这个写法是合法的。

9. 执行以下代码，两个 ReferenceEquals 的结果分别是？

A. True / True　B. False / True　C. True / False　D. False / False

  • 正确答案：B
  • 解析：StringBuilder.ToString() 生成的是运行时新字符串，不在驻留池，故第一个为 False；string.Intern 返回驻留池中与内容相同的实例，第二个为 True。

10. 用反射 GetMethod(“X”).Invoke(…) 调用某个方法，编辑器下正常，IL2CPP 打包后可能失败。最可能的原因是？
A. 反射不能用字符串方法名　B. Invoke 只能调用 public 方法　C. IL2CPP 不支持任何反射　D. 代码剥离把未被静态引用的方法裁掉

  • 正确答案：D
  • 解析：IL2CPP 构建会做托管代码剥离，仅被反射字符串引用的成员可能被裁掉；需要通过 link.xml、[Preserve] 或强引用方式保留。

11. 要用缓存长期持有大对象，又不想阻止 GC 回收它，较合适的做法是？
A. 用 WeakReference<T>　B. 用 static 字段强引用　C. 把对象设为 DontDestroyOnLoad　D. 用 Dictionary<string, object> 强引用缓存

  • 正确答案：A
  • 解析：WeakReference<T> 不阻止目标被回收；TryGetTarget 能安全判断对象是否仍存活。强引用缓存会让对象无法回收，是内存泄漏的常见来源。

12. 下列不能直接重载的运算符是？
A. +　B. ==　C. true　D. =

  • 正确答案：D
  • 解析：赋值运算符 = 不能重载；==/!= 必须成对重载，true/false 也必须成对。+ 等算术运算符可重载。

13. 一个类同时实现了 IDisposable 和终结器。在 Dispose 中较规范的做法是？
A. 只调用 GC.Collect() 强制触发一次回收　B. 调用 GC.SuppressFinalize(this)　C. 调用 GC.KeepAlive(this) 让对象保持存活　D. 手动调用 Finalize 完成资源释放

  • 正确答案：B
  • 解析：Dispose 已释放资源后调用 GC.SuppressFinalize(this)，告诉 GC 不必再执行终结器，避免重复释放与多一次终结开销。Dispose 还应保证可重复调用。

14. 某类型不想修改自身、又希望支持「按价格排序」和「按名称排序」两套规则，应优先使用？
A. 让类型实现多个 IComparable<T>　B. 用 Equals 重写比较　C. 定义两个实现 IComparer<T> 的比较器　D. 用 == 重载比较

  • 正确答案：C
  • 解析：IComparable<T> 是类型自身的默认比较；多种外部排序规则应使用 IComparer<T>，通过 Sort 传入，保持类型无侵入。

15. switch 模式匹配中，case int i when i > 0: 的匹配条件是？
A. 只要类型为 int 就匹配　B. 类型为 int 且 i > 0 同时成立才匹配　C. when 子句只用于 default　D. 会先执行 when 再判断类型

  • 正确答案：B
  • 解析：when 是在模式匹配成功之后追加的守卫条件，二者都满足才会进入该分支；不满足时会继续尝试后续 case。

16. 在 checked 块中执行 int.MaxValue + 1，结果是？
A. 回绕为 int.MinValue　B. 抛出 OverflowException　C. 编译期报错　D. 自动提升为 long

  • 正确答案：B
  • 解析：C# 默认是 unchecked，溢出回绕；checked 块会开启整型溢出检查并抛出 OverflowException。该设置不影响浮点数。

17. 自定义特性类时，AttributeUsage 的哪个属性控制它能否被派生类继承？
A. Inherited　B. AllowMultiple　C. ValidOn　D. Targets

  • 正确答案：A
  • 解析：Inherited 控制特性是否随派生类继承；AllowMultiple 控制能否重复标注；ValidOn 指定可应用的目标。

18. 关于 int[][] 与 int[,]，下列说法正确的是？
A. int[][] 是交错数组　B. 两者只是语法不同，内存布局完全一致　C. int[,] 是交错数组　D. 两者都是连续矩形数组

  • 正确答案：A
  • 解析：int[][] 是数组的数组，每一行是独立引用，长度可不同；int[,] 在内存中连续、行列固定，访问与缓存表现不同。

19. 需要在运行时根据平台配置初始化一个不可变的值，较合适的是？
A. const　B. readonly 实例字段　C. static readonly　D. 普通 static 字段

  • 正确答案：C
  • 解析：const 必须编译期常量；static readonly 可在静态构造函数或声明处运行时初始化，且初始化后不可再赋值，适合平台相关配置。

20. 以下 struct 通过接口方法自增后，输出是？

A. 1　B. 0　C. 2　D. 编译错误

  • 正确答案：B
  • 解析：struct 转为接口会发生装箱，it.Inc() 修改的是装箱副本，原变量 s.X 仍为 0。通过接口修改结构体是不可靠的，这是装箱语义的典型边界。

Unity 引擎基础

21. 刚体在固定物理帧移动、渲染帧插值时出现明显抖动。开启 Rigidbody.interpolation 后仍抖动，最可能的原因是？
A. 插值只能在 Update 中生效，FixedUpdate 无法参与　B. 在 FixedUpdate 中直接改了 transform.position　C. 没有开启连续碰撞检测，导致显示与物理不同步　D. 质量设置过低，物理更新频率被引擎自动降级

  • 正确答案：B
  • 解析：插值基于物理帧的刚体位置做显示平滑；若同时直接写 transform.position，会破坏物理内部状态与插值基准，导致抖动。移动应使用 MovePosition 或速度、力。

22. 某高速弹丸使用 Rigidbody 的 Extrapolate 插值且碰撞异常，最合理的处理是？
A. 继续用外推，速度越快越准　B. 提高渲染帧率即可　C. 改用 Interpolate　D. 关闭刚体

  • 正确答案：C
  • 解析：Extrapolate 按速度预测，可造成穿越或错误位置；高速物体应开启连续碰撞检测，并优先用 Interpolate 做显示平滑，避免依赖外推。

23. 角色需要贴合地面移动、受斜坡与台阶约束，且不参与受力的布娃娃物理。较合适的是？
A. Rigidbody + AddForce　B. BoxCollider 不带刚体　C. Rigidbody 设为 Kinematic 后直接写 transform.position　D. CharacterController

  • 正确答案：D
  • 解析：CharacterController 专为角色移动设计，自带胶囊体、斜坡与台阶处理，不依赖受力；Rigidbody 更适合受物理力与碰撞模拟的对象。

24. 在编辑器下运行时修改一个 ScriptableObject 资产字段，可能带来什么风险？
A. 无风险，退出播放会自动还原　B. 会触发编译　C. 只影响当前帧　D. 会修改磁盘上的资产本身

  • 正确答案：D
  • 解析：运行时对 ScriptableObject 资产的赋值会写入该资产，编辑器下可能被保存下来造成数据污染；需要临时修改时应 Instantiate 出副本。

25. 用 LoadSceneMode.Additive 叠加加载场景后，想让新场景中的对象成为后续 Instantiate 的默认父级，应调用？
A. SceneManager.MoveGameObjectToScene　B. SceneManager.UnloadSceneAsync　C. SceneManager.SetActiveScene(newScene)　D. DontDestroyOnLoad

  • 正确答案：C
  • 解析：SetActiveScene 决定新创建对象所属的活动场景与默认父级；MoveGameObjectToScene 用于移动已有对象，UnloadSceneAsync 用于卸载。

26. Physics.Raycast 想命中触发器，同时只检测指定层，正确的参数组合是？
A. 只传 LayerMask，触发器默认一定会命中，无需额外设置　B. 传 LayerMask 并设置 QueryTriggerInteraction.Collide　C. 把触发器层从 LayerMask 中剔除，避免命中触发器　D. 必须改用 Physics.OverlapSphere，Raycast 不支持触发器

  • 正确答案：B
  • 解析：物理查询默认可能忽略触发器，是否命中由 QueryTriggerInteraction 控制；LayerMask 负责层过滤。二者职责不同，需要组合使用。

27. 想让一个刚体瞬间获得一个速度变化，且不受质量影响，应使用？
A. ForceMode.VelocityChange　B. ForceMode.Acceleration　C. ForceMode.Impulse　D. ForceMode.Force

  • 正确答案：A
  • 解析：VelocityChange 直接改变速度、无视质量；Impulse 是冲量，效果与质量有关；Force/Acceleration 是持续力/加速度，需乘以时间步长。

28. 对 Rigidbody 开启 Interpolate 后，还在 Update 中每帧修改 transform.rotation，最可能出现的问题是？
A. 与物理插值互相覆盖　B. 只影响碰撞检测　C. 刚体自动转为 Kinematic　D. 插值自动禁用，无影响

  • 正确答案：A
  • 解析：Interpolate 会基于物理帧状态插值渲染姿态；在 Update 中直接写 transform 会覆盖插值结果，造成显示与物理不同步。旋转应使用 MoveRotation 或 angularVelocity。

29. 一个 Kinematic 刚体与普通碰撞体发生接触，能否触发 OnTriggerEnter？
A. 可以，前提是至少一方为 isTrigger 且 Kinematic 参与查询　B. 不能，Kinematic 刚体不会产生任何碰撞或触发回调　C. 只有 Dynamic 与 Dynamic 之间才能触发，其他组合无效　D. 必须把 Kinematic 改为 Static 后，触发回调才会生效

  • 正确答案：A
  • 解析：触发器回调要求至少一方带 Rigidbody，Kinematic 刚体可以触发；是否影响其他刚体由 detectCollisions 等设置决定，与是否 Dynamic 无必然关系。

30. Time.fixedDeltaTime 设为 0.02、某帧卡顿耗时 0.5 秒时，Unity 默认会怎样处理物理步进？
A. 自动降低 fixedDeltaTime　B. 补跑 25 次 FixedUpdate，无上限　C. 直接跳过所有物理　D. 受 Time.maximumDeltaTime 限制

  • 正确答案：D
  • 解析：Unity 用 maximumDeltaTime 限制单帧最多补偿的时间，防止因卡顿补跑过多 FixedUpdate 造成恶性循环；超出部分会被丢弃或调整。

31. 移动端既想锁 30 帧、又想避免垂直同步干扰，正确设置是？
A. QualitySettings.vSyncCount = 1，Application.targetFrameRate = 30　B. 只设 vSyncCount = 1 即可　C. QualitySettings.vSyncCount = 0，Application.targetFrameRate = 30　D. 只设 Application.targetFrameRate = -1

  • 正确答案：C
  • 解析：vSyncCount 会覆盖 targetFrameRate；要使用 targetFrameRate 锁帧，应先把 vSyncCount 设为 0。

32. 相机 Culling Mask 设置为只渲染 Enemy 层，是否会影响 Physics.Raycast 的命中结果？

50. 一个资源包主要面向首次下载、加载频率低，另一个资源包需要频繁随机加载。压缩方式较合理的组合是？

  • 正确答案：A
  • 解析：LZMA 压缩率高、包体小，但加载时通常需整体解压，适合下载优先；LZ4 可随机读取、加载快，适合频繁加载。应按包的使用特征选择。

51. AssetBundle.Unload(false) 之后，已从该包加载的贴图还能用吗？何时真正释放？
A. 立即释放，贴图不可用　B. 一定内存泄漏，永远不释放　C. 需要使用 Resources.UnloadAsset 才能保留　D. 仍可用，因为只卸载了包

  • 解析：Unload(false) 释放包本身，已加载资源继续存活；资源实际释放依赖引用计数归零与后续卸载/回收。Unload(true) 会强制卸载资源，可能导致引用变 missing。

  • 正确答案：D
  • 解析：AssetBundle 依赖由 Manifest 记录，循环依赖会让加载顺序无法确定、打包器也可能报错；应把共享资源抽到无环的公共包中。

53. 使用 Addressables 的 LoadAssetAsync 后，正确的释放方式是？

54. 在场景切换后调用 Resources.UnloadUnusedAssets，其主要代价是？

性能优化

66. SetPass Call 与 DrawCall 的区别是？
A. 两者完全等价　B. SetPass Call 统计渲染状态切换次数　C. SetPass Call 是三角面数　D. DrawCall 只统计 UI

  • 正确答案：B
  • 解析：SetPass 反映 Shader/材质等状态切换，DrawCall 反映提交绘制次数；批处理可让一次 SetPass 服务多个 DrawCall。优化时要同时关注两者与 Batches。

67. 静态合批能减少 DrawCall，但主要代价是？
A. 对象不能再移动　B. 必须每帧重建　C. 会降低分辨率　D. 只能用于 UI

  • 正确答案：A
  • 解析：静态合批把多个静态网格合并成一个大网格，减少绘制调用，但会多一份合并网格内存，且这些对象在运行时不能移动。

68. 动态合批无法生效的常见原因是？
A. 对象使用相同材质，导致合批请求被引擎直接忽略　B. 没有开启静态合批，动态合批因此无法正常生效　C. 对象数量太少，达不到动态合批所需的最小阈值　D. 顶点数超过上限、使用不同材质或非统一缩放导致无法合并

  • 正确答案：D
  • 解析：动态合批有顶点数限制，且要求材质相同、变换满足条件；不同材质、大网格、非统一缩放等都会导致合批失败。

69. GPU Instancing 相比静态/动态合批的主要优势是？

  • 正确答案：B

  • 解析：链地址法每个桶维护链表/红黑树，删除方便但可能有指针开销；开放寻址法通过线性/二次探测寻找空位，缓存更友好但删除需墓碑标记且装载因子敏感。

109. 归并排序相比快速排序的典型优劣是？
A. 最坏 O(n²)　B. 更快且不需要额外空间　C. 不稳定但省内存　D. 稳定、最坏 O(n log n)

  • 正确答案：D
  • 解析：归并排序是稳定排序，最坏与平均均为 O(n log n)，但需要 O(n) 额外空间；快排平均更快、原地，但最坏 O(n²) 且不稳定。

110. 在二叉搜索树中求某节点的中序后继，O(h) 的做法是？
A. 中序遍历整棵树　B. 若右子树非空取右子树最左节点　C. 必须排序后查找　D. 无法在 O(h) 内完成

  • 正确答案：B
  • 解析：中序后继分两种情况：有右子树时是右子树的最小节点；无右子树时向上找第一个使当前子树位于其左子树的祖先。沿路径移动，复杂度 O(h)。

二、主观题

主观题共 12 题。简答题请写出关键点与结论；编程题请给出完整代码、边界处理与复杂度分析。参考答案默认隐藏，建议先自行作答再展开对照。

1.（简答）请说明协程与 Invoke 的区别，以及常见 yield 指令（yield return null、WaitForSeconds、WaitForFixedUpdate、WaitForEndOfFrame）的恢复时机。

题目： 请说明协程与 Invoke 的区别，并说明 yield return null、WaitForSeconds、WaitForFixedUpdate、WaitForEndOfFrame、WaitForSecondsRealtime 各自的恢复时机与受 timeScale 影响的情况。

标准答案：

Invoke：按延迟调用方法（一次或重复），不能跨帧暂停、不能带参数、不能暂停/恢复。
协程：返回 IEnumerator，由 Unity 调度，可跨帧、可带参、可暂停/恢复/停止，控制更灵活。
常见 yield 指令的恢复时机：

  • yield return null：下一帧 Update 之后；
  • WaitForSeconds：缩放时间到达后；
  • WaitForSecondsRealtime：真实时间到达后；
  • WaitForFixedUpdate：下一次 FixedUpdate 之前；
  • WaitForEndOfFrame：当前帧渲染完成之后。

2.（简答）请说明 Unity 中 MonoBehaviour 单例的实现方式，以及跨场景保留、防止重复实例时需要注意什么。

题目： 请说明 Unity 中 MonoBehaviour 单例的几种实现方式，并重点分析跨场景保留、重复实例、场景切换后引用失效与线程安全等注意点。

标准答案：

实现：静态 Instance 字段 + Awake 中判空赋值，重复实例销毁；跨场景可 DontDestroyOnLoad。
注意事项：

  • 切换场景默认销毁对象，需要 DontDestroyOnLoad；
  • 重复进入场景会创建多个实例，需判重销毁；
  • 播放模式退出/域重载时静态字段可能残留，应在 OnDestroy 清理；
  • 不要在 OnDestroy 中访问可能已销毁的其他对象。

3.（简答）请说明对象池的适用场景，以及实现时必须处理的关键问题。

题目： 请说明对象池的适用场景与不适用场景，并给出实现时必须处理的关键问题：容量策略、状态重置、异常归还、预暖与内存上限。

标准答案：

适用场景：频繁创建/销毁且状态可复用的对象（子弹、特效、列表项）。
关键问题：

  • 回收时重置状态，避免取出“脏对象”；
  • 设置池上限，避免内存只增不减；
  • 取出与回收必须成对，避免泄漏；
  • 必要时考虑线程安全与多池分类管理。

4.（简答）请说明 ScriptableObject 的用途与优势，以及它与 MonoBehaviour 的区别。

题目： 请说明 ScriptableObject 的用途与优势，并从生命周期、挂载方式、序列化、运行时修改资产、内存与热更角度说明它与 MonoBehaviour 的区别。

标准答案：

用途：以资源形式存储可序列化的共享数据，如配置表、游戏参数、技能数据。
优势：

  • 不依附 GameObject，可被多个对象引用，节省内存；
  • 可在 Inspector 编辑，可作为资源热更；
  • 适合数据驱动设计。
    区别：MonoBehaviour 必须挂载在 GameObject 上并参与帧循环；ScriptableObject 是纯数据资产。

5.（简答）请说明 C# 迭代器（yield）的状态机原理，以及它与“返回数组”在内存与执行时机上的差异。

题目： 请说明 C# 迭代器（yield）的状态机原理，并比较它与一次性返回数组在内存占用、执行时机、异常与 Dispose 行为上的差异。

标准答案：

编译器会把含 yield 的方法编译成一个状态机类，保存执行位置与局部变量。
调用方法时不会立即执行方法体；每次 MoveNext() 才推进到下一个 yield 并暂停。
与返回数组相比：

  • 迭代器惰性计算，额外空间 O(1)，适合大数据流；
  • 返回数组一次性计算，需要 O(n) 空间。

6.（简答）请说明观察者/事件系统的优点与常见坑，并给出一个健壮事件中心的设计要点。

题目： 请说明观察者/事件系统的优点与常见坑，并给出一个健壮事件中心的设计要点，覆盖订阅退订、异常隔离、线程安全与生命周期。

标准答案：

优点：一对多通知、发布者与订阅者解耦、易于扩展。
常见坑：

  • 忘记退订导致内存泄漏/悬挂引用；
  • 回调中增删监听者导致遍历异常（应先复制一份再触发）；
  • 某个监听者抛异常会中断后续监听者（可逐个 try/catch）；
  • 事件顺序不保证，避免依赖顺序。

7.（简答）请说明 LOD、遮挡剔除（Occlusion Culling）、视锥剔除（Frustum Culling）三者的区别与作用。

题目： 请说明 LOD、遮挡剔除（Occlusion Culling）、视锥剔除（Frustum Culling）三者的原理、区别、开销与适用场景，并说明各自常见的配置误区。

标准答案：

视锥剔除：剔除不在相机视锥体内的物体，Unity 默认开启。
遮挡剔除：剔除被其他物体挡住、不可见的物体，需烘焙。
LOD：根据物体与相机距离切换不同精度模型，降低远距离渲染开销。三者都是减少渲染量的优化手段。

8.（简答）请比较 async/await、Unity 协程、UniTask 三者的区别与适用场景。

题目： 请比较 async/await、Unity 协程、UniTask 三者在调度模型、返回值、异常传播、取消、GC 与线程切换上的区别，并给出各自适用场景。

标准答案：

协程：由 Unity 原生调度、主线程、无返回值无取消、有 GC。
async/await：C# 语言特性，原生 Task 可能在线程池执行，操作 Unity API 有生命周期与线程坑。
UniTask：struct + PlayerLoop 驱动，主线程、零分配、可取消、可组合、可绑定 Destroy，适合 Unity 异步。

9.（简答）请简述 C# 垃圾回收（GC）的基本原理，以及减少 GC 的常用方法。

题目： 请简述 C# 垃圾回收的基本原理（分代、标记-清除/压缩、触发时机），并从分配来源、对象池、缓存、装箱与闭包等角度说明减少 GC 的常用方法。

标准答案：

GC 自动回收托管堆上不再被引用的对象，采用分代回收（0/1/2 代），大对象进入 LOH。
减少 GC：避免频繁 new、字符串拼接、装箱、闭包捕获、LINQ；使用对象池、缓存、结构体、StringBuilder、避免每帧分配。

10.（简答）请对比 Resources、AssetBundle、Addressables 三种资源加载方式。

题目： 请从加载方式、依赖管理、引用计数、卸载、热更、包体与开发效率等维度对比 Resources、AssetBundle、Addressables，并给出选型建议。

标准答案：

Resources：简单但资源全部打进包体、难管理，不推荐大量使用。
AssetBundle：可分包、热更新、按需加载，但需自己管理依赖、引用计数、卸载、构建。
Addressables：在 AB 之上提供高层封装，自动处理依赖、引用计数、异步与远程更新，降低管理成本。

11.（简答）请列举 Unity 中 UI 性能优化的常见手段。

题目： 请列举 Unity UI 性能优化的常见手段，覆盖 Canvas 重建、DrawCall/合批、Raycast、布局、Overdraw、图集与长列表，并说明各自的适用条件。

12.（简答）请说明 AssetBundle 的依赖管理与引用计数机制，以及常见的资源泄漏原因。

题目： 请说明 AssetBundle 的依赖管理与引用计数机制，并列举常见的资源泄漏原因与排查方法，覆盖 Unload、Handle 释放、场景切换与异常路径。

标准答案：

依赖管理：通过 Manifest 记录 AB 之间的依赖；加载资源前需先加载其依赖包；公共资源应抽到单独 AB，避免重复打包与内存翻倍。
