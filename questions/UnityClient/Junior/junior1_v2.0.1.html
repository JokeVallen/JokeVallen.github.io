一、客观题

C# 基础

1. 值类型变量通常存储在？
A. 托管堆　B. 静态数据区　C. 线程本地存储　D. 栈（或作为字段内联在所属对象中）

  • 正确答案：D
  • 解析：值类型通常分配在栈上；作为引用对象的字段时内联在堆对象中。引用类型对象分配在托管堆上。

2. object o = 10; 这行代码发生了什么？
A. 拆箱，把引用类型还原为值类型　B. 隐式引用转换，不产生额外开销　C. 装箱，会在托管堆分配对象　D. 编译错误，值类型不能赋给 object

  • 正确答案：C
  • 解析：值类型 int 赋给 object 引用类型即装箱，会在托管堆分配对象并复制值，有性能开销。

3. 关于 string 的说法，正确的是？
A. string 是值类型，赋值时复制内容　B. 每次修改都会生成新的字符串对象　C. string 为可变引用类型　D. == 比较的是两个字符串的引用地址

  • 正确答案：B
  • 解析：string 是引用类型但不可变，任何修改都会生成新对象；== 被重载为值比较。

4. 关于 const 和 readonly，正确的是？
A. readonly 是编译时常量，const 是运行时常量　B. const 是编译时常量且隐式 static　C. 两者都可以是实例字段　D. readonly 字段无法在构造函数中赋值

  • 正确答案：B
  • 解析：const 编译期确定、隐式 static、不能是实例字段；readonly 运行期可赋值一次、可为实例字段。

5. 关于 ref 和 out，正确的是？
A. out 参数必须在传入前初始化　B. ref 参数必须在方法内赋值　C. out 参数必须在方法内赋值　D. 两者都不能用于值类型

  • 正确答案：C
  • 解析：ref 传入前必须初始化；out 传入前不用初始化但方法内必须赋值；两者都可用于值类型。

6. 关于接口和抽象类，正确的是？
A. 接口可以包含实例字段　B. 抽象类可以多重继承　C. 接口可以被实例化　D. 一个类可以实现多个接口

  • 正确答案：D
  • 解析：接口不能含实例字段、不能实例化；C# 类只能单继承抽象类，但可实现多个接口。

7. struct 的默认值/默认构造，正确的是？
A. struct 不能声明任何构造函数　B. struct 的默认值：各字段为 0 / null　C. struct 可以声明析构函数　D. struct 无法实现接口

  • 正确答案：B
  • 解析：struct 默认值各字段为 0 / null；struct 可声明构造函数、不能有析构函数、不能继承类。

8. 需要按键频繁查找，最适合的数据结构是？
A. Dictionary<TKey,TValue>　B. List<T>　C. HashSet<T>　D. SortedList<TKey,TValue>

  • 正确答案：A
  • 解析：Dictionary<TKey,TValue> 基于哈希，按键查找平均 O(1)；List 为 O(n)，SortedList 为 O(log n)。

9. object o = 10; int i = (int)o; 中第二句发生了什么？
A. 无操作，直接复制引用　B. 装箱（值类型 → 引用类型）　C. 拆箱（引用类型 → 值类型）　D. 编译错误，object 不能强制转换为 int

  • 正确答案：C
  • 解析：引用类型 object 转回值类型 int 即拆箱，做类型检查后取值，通常不产生堆分配。

10. StringBuilder 相比直接用 string 拼接的优势是？
A. 每次拼接都会生成新的字符串对象　B. 线程安全，适合多线程拼接　C. 可变，减少频繁的临时字符串分配　D. 底层是链表，随机访问更快

  • 正确答案：C
  • 解析：string 拼接会不断产生临时字符串；StringBuilder 内部维护可变缓冲，适合大量拼接。

11. 关于 static 成员，正确的是？
A. 属于类型，所有实例共享　B. 属于实例，每个对象一份　C. 不能被类外部访问　D. 每次 new 都会复制一份

  • 正确答案：A
  • 解析：static 成员属于类型而非实例，所有实例共享；不能通过实例访问（C# 不允许）。

12. 关于 virtual 和 abstract，正确的是？
A. virtual 有默认实现可被重载，abstract 无实现且必须被重载　B. 两者完全一样，只是关键字不同　C. abstract 类可以直接实例化　D. virtual 有默认实现可被重写，abstract 无实现且必须被子类重写

  • 正确答案：D
  • 解析：virtual 有默认实现可被 override；abstract 无实现且必须在子类重写，abstract 类不能实例化。

13. sealed 关键字的作用是？
A. 允许继承，但禁止重写　B. 提高运行性能　C. 禁止继承（类）或禁止重写（方法）　D. 必须与 abstract 一起使用

  • 正确答案：C
  • 解析：sealed 用于禁止类被继承或方法被重写；不能与 abstract 用于同一方法。

14. 关于委托（delegate）与事件（event），正确的是？
A. 两者完全一样，可以互换　B. 事件不能多播　C. 事件是对委托的封装，外部只能 += / -=，不能直接调用或赋值　D. 委托不能用 +=

  • 正确答案：C
  • 解析：event 是对 delegate 的封装，外部只能 += / -=，不能直接赋值或调用，保证封装性。

15. 关于 int?（可空类型），正确的是？
A. int? 是 Nullable<int> 的简写，可以赋值为 null　B. int? 可以赋 null，但它的底层是引用类型　C. int? 与 int 完全等价，只是写法不同　D. int? 的默认值是 0，而不是 null

  • 正确答案：A
  • 解析：int? 是 Nullable<int> 的简写，可赋 null；底层是 struct 而非引用类型，默认值为 null。

16. 关于泛型约束，正确的是？
A. where T : struct 表示 T 必须是引用类型　B. where T : class 表示 T 必须是值类型　C. 泛型类型参数不能添加多个约束　D. where T : new() 表示 T 必须具有公共无参构造函数

  • 正确答案：D
  • 解析：where T : new() 要求 T 有公共无参构造函数；struct 约束值类型，class 约束引用类型。

17. 关于 try / catch / finally，正确的是？
A. finally 无论 try 是否发生异常（且未被提前终止）都会执行　B. finally 只在 try 中发生异常时才执行　C. try 可以单独出现，不需要 catch 或 finally　D. throw 抛出异常后，同一方法的 finally 不会执行

  • 正确答案：A
  • 解析：finally 无论是否异常都会执行（除非进程终止等）；catch 只在异常类型匹配时执行。

18. 关于 yield return，正确的是？
A. yield return 会创建新线程执行后续代码　B. yield return 可以放在带 catch 的 try 块中　C. 每次 MoveNext() 执行到下一个 yield return 并暂停，保存当前状态　D. 迭代器方法在调用时会立即执行完整个方法体

  • 正确答案：C
  • 解析：yield return 是惰性迭代器；每次 MoveNext 推进到下一个 yield 并暂停，保存当前状态。

19. 以下关于 C# 属性（property）描述正确的是？
A. 属性就是字段，直接访问内存　B. 属性的 get / set 会被编译为 get_ / set_ 方法　C. 属性不能包含任何逻辑　D. 自动属性不能有访问修饰符

  • 正确答案：B
  • 解析：属性本质是方法（get_ / set_），不是字段；可包含逻辑，也可只读/只写。

20. 关于 Lambda 表达式与闭包，正确的是？
A. Lambda 只能捕获方法体中的局部变量，不能捕获类的实例或静态变量　B. Lambda 一定是静态方法，不会产生任何分配　C. 捕获的外部局部变量会被提升到编译器生成的闭包类中，可能产生堆分配　D. 闭包捕获的是变量的值，之后外部修改变量不会影响闭包

  • 正确答案：C
  • 解析：闭包会把捕获的局部变量提升到编译器生成的显示类中，产生堆分配；捕获的是变量本身。

21. 关于 Func 与 Action，正确的是？
A. Func 有返回值，Action 无返回值　B. 两者都有返回值　C. 两者都没有返回值　D. Func 有返回值，Action 有返回值

  • 正确答案：A
  • 解析：Func 有返回值，Action 无返回值；两者都是委托，可带多个参数。

22. 关于 using 语句，正确的是？
A. using 不能用于值类型　B. using 不能与 try 一起使用　C. 作用域结束时自动调用 Dispose()，发生异常时也会调用　D. 作用域结束时自动调用 Dispose()，发生异常时不会调用

  • 正确答案：C
  • 解析：using 编译为 try / finally，作用域结束或异常时都会调用 Dispose()；要求实现 IDisposable。

23. 关于 C# 泛型，正确的是？
A. 泛型在运行时总是退化为 object，因此必然发生装箱　B. 泛型可避免值类型的装箱 / 拆箱，提升性能　C. 泛型不能有多个类型参数　D. 泛型类型参数不能添加约束

  • 正确答案：B
  • 解析：泛型为值类型生成专用代码，避免装箱/拆箱；支持多个类型参数与约束。

24. 关于 IEnumerable<T> 与 IEnumerator<T>，正确的是？
A. 两者完全等价，可以互换　B. IEnumerable<T> 提供 GetEnumerator()，IEnumerator<T> 提供 MoveNext() / Current　C. IEnumerator<T> 只能通过 foreach 调用　D. IEnumerable<T> 提供 MoveNext() / Current

  • 正确答案：B
  • 解析：IEnumerable 提供 GetEnumerator()，IEnumerator 提供 MoveNext() / Current；foreach 依赖二者。

Unity 引擎基础

25. 生命周期函数的正确顺序是？
A. Awake → OnEnable → Start　B. OnEnable → Awake → Start　C. Start → Awake → OnEnable　D. Awake → Start → OnEnable

  • 正确答案：A
  • 解析：首次激活顺序为 Awake → OnEnable → Start：Awake 初始化自身，OnEnable 做启用逻辑，Start 在首次更新前。

26. 物理相关的更新应在哪个函数中进行？
A. FixedUpdate　B. Update　C. LateUpdate　D. OnGUI

  • 正确答案：A
  • 解析：物理计算应放在 FixedUpdate，按固定步长执行，用 Time.fixedDeltaTime。

27. 让移动速度与帧率无关，位移应乘以？
A. Time.time　B. Time.unscaledTime　C. Time.fixedDeltaTime　D. Time.deltaTime

  • 正确答案：D
  • 解析：Update 中与帧率无关的位移应乘 Time.deltaTime；FixedUpdate 中才用 fixedDeltaTime。

28. 触发器（Trigger）检测需要满足？
A. 双方都必须有 Rigidbody 且 Collider 勾选 IsTrigger　B. 至少一方有 Rigidbody（或 CharacterController）且 Collider 勾选 IsTrigger　C. 只要有 Collider 且勾选 IsTrigger 即可　D. 只要有 Rigidbody 即可

  • 正确答案：B
  • 解析：触发器检测要求至少一方有 Rigidbody（或 CharacterController），且 Collider 勾选 IsTrigger。

29. 关于 Time.timeScale = 0，正确的是？
A. Time.deltaTime 变为 0，Update 仍会调用　B. Time.deltaTime 不会变为 0，Update 仍会调用 　C. WaitForSeconds 仍按真实时间推进　D. Time.unscaledTime 也停止推进

  • 正确答案：A
  • 解析：timeScale=0 时 deltaTime 变 0、物理与缩放等待暂停，但 Update 仍每帧调用；unscaledTime 不受影响。

30. 摄像机平滑跟随目标，通常放在哪个函数？
A. Update　B. LateUpdate　C. FixedUpdate　D. Awake

  • 正确答案：B
  • 解析：相机跟随应放在 LateUpdate，保证目标在 Update 移动完毕后再更新，避免抖动。

31. 关于 Destroy(obj) 与 Destroy(obj, 2f) 描述正确的是？
A. Destroy(obj) 可能在当前帧 Update 之前销毁，Destroy(obj, 2f) 延迟 2 秒销毁　B. Destroy(obj) 会立即销毁　C. Destroy(obj) 在当前帧 Update 之后销毁，Destroy(obj, 2f) 延迟 2 秒销毁　D. Destroy(obj, 2f) 在延迟 2 秒后立即销毁

  • 正确答案：C
  • 解析：Destroy(obj) 在当前帧 Update 之后销毁（并非 DestroyImmediate 立即销毁）；Destroy(obj,t) 延迟 t 秒。

32. 控制两个 Layer 之间是否发生物理碰撞的是？
A. Physics 的 Layer Collision Matrix　B. Tag　C. Sorting Layer　D. Layer 本身的编号

  • 正确答案：A
  • 解析：两个 Layer 是否发生物理碰撞由 Physics 的 Layer Collision Matrix 控制；Tag 与渲染无关。

33. Awake 与 Start 的区别，正确的是？
A. Start 是否调用与对象激活状态无关　B. Awake 在对象未激活时依旧会正常调用一次　C. Start 在对象未激活时依旧会正常调用一次　D. Awake 仅在对象首次激活时正常调用一次

  • 正确答案：D
  • 解析：Awake 在对象激活时调用一次；Start 在组件启用且首次 Update 前调用。未激活对象不会调用 Awake。

34. 关于 OnEnable 描述正确的是？
A. 仅在对象首次激活时调用一次　B. 每次组件/对象被激活或启用时调用　C. 按固定频率调用　D. 对象销毁时调用

  • 正确答案：B
  • 解析：OnEnable 每次对象/组件被启用或激活时调用，与 OnDisable 成对，适合订阅/显示等对称逻辑。

35. 关于 Invoke 与协程，正确的是？
A. Invoke 只能按延迟调用方法，协程可跨帧、带参数、可暂停/停止，控制更灵活　B. 两者完全相同，可互换　C. Invoke 比协程更灵活　D. 协程启动后不能停止

  • 正确答案：A
  • 解析：Invoke 只能延迟调用方法，不能跨帧暂停、不能传参；协程可跨帧、传参、暂停/停止，更灵活。

36. 关于 Instantiate 的返回值，正确的是？
A. 返回 void，克隆对象只能通过回调获取　B. 返回 bool，表示是否实例化成功　C. 返回克隆出的对象，类型与传入的预制体/组件一致　D. 返回被实例化对象的 Transform

  • 正确答案：C
  • 解析：Instantiate 返回克隆出的对象，类型与传入的预制体/组件一致；不是 void/bool。

37. 关于 FindObjectOfType，正确的是？
A. 高效，推荐每帧调用　B. 不影响性能，与直接引用一样　C. 会遍历场景，性能较差，应缓存结果　D. 只能查找未激活对象

  • 正确答案：C
  • 解析：FindObjectOfType 会遍历场景，性能较差；应缓存结果，避免在 Update 中频繁调用。

38. UGUI 中决定同一 Canvas 下 UI 元素渲染先后顺序的是？
A. 在 Hierarchy 视图下的顺序　B. Tag　C. Layer　D. 游戏对象名字

  • 正确答案：A
  • 解析：同一 Canvas 下 UI 的渲染先后顺序由在 Hierarchy 视图下的顺序决定。

39. Physics.Raycast 的作用是？
A. 检测两个 Collider 是否重叠　B. 检测射线与碰撞体的相交　C. 获取对象的所有组件　D. 计算两点距离

  • 正确答案：B
  • 解析：检测射线与碰撞体的相交，返回是否命中；常用于点击、子弹、视线检测。

40. 关于 Unity 序列化，正确的是？
A. [SerializeField] 可以让 protected 字段被序列化　B. public Dictionary<string,int> dict; 可以被直接序列化　C. 接口类型字段可以直接被序列化　D. static 字段也会被序列化

  • 正确答案：A
  • 解析：Unity 只序列化 public 字段、带 [SerializeField] 的字段、带 [Serializable] 的类型等；Dictionary/接口/static 不行。

41. 关于 Animator，正确的是？

二、主观题

1.（简答）Update、FixedUpdate、LateUpdate 的区别与使用场景

标准答案：

回调 调用时机 时间增量 典型用途
Update 每帧一次，频率随帧率变化 Time.deltaTime 输入、UI 刷新、非物理逻辑
FixedUpdate 固定时间步长（默认 0.02s / 50Hz），一帧可能 0 次或多次 Time.fixedDeltaTime 物理计算（Rigidbody、力、碰撞）
LateUpdate 所有 Update 之后，每帧一次 Time.deltaTime 相机跟随、依赖目标位置的逻辑

要点：

  • 物理相关逻辑应放在 FixedUpdate，不要在 Update 中直接做物理；
  • 相机跟随放 LateUpdate，保证目标在 Update 中移动完毕后再更新相机；
  • Update 与 LateUpdate 与帧率相关，位移须乘 deltaTime。

2.（简答）Unity 协程在什么情况下会停止/失效？

标准答案：

  1. GameObject.SetActive(false)：协程停止，重新激活也不会自动恢复；
  2. GameObject 被 Destroy：协程终止；
  3. 主动调用 StopCoroutine / StopAllCoroutines；
  4. 协程内抛出未捕获异常：协程静默终止并打印异常；
  5. 边界：MonoBehaviour.enabled = false 不会停止协程；真正使其停止的是 GameObject 失活或销毁。

5.（简答）值类型 vs 引用类型 + 装箱拆箱

标准答案：

值类型 vs 引用类型：

维度 值类型 引用类型
存储 局部变量在栈；字段内联在对象中 对象在托管堆，变量保存引用
赋值 复制值 复制引用（指向同一对象）
继承 不能继承类，可实现接口 支持继承与多态
默认值 0 / false null

装箱与拆箱：

  • 装箱：值类型 → object 或接口，在堆上分配对象并复制值，有开销；
  • 拆箱：object → 值类型，做类型检查后取值，通常不产生堆分配；
  • 应在高频路径避免装箱，泛型可有效避免。

6.（简答）Awake / Start / OnEnable

标准答案：

  • Awake：脚本实例加载时调用一次，用于初始化；只要 GameObject 激活即调用；
  • OnEnable：组件/对象每次被启用或激活时调用，与 OnDisable 成对，可多次调用；
  • Start：第一次 Update 前调用一次，且仅在组件 enabled 时执行。

调用顺序：Awake → OnEnable → Start。

9.（简答）try / catch / finally 的执行顺序与 finally + return

标准答案：

  • 执行顺序：先执行 try；若发生异常且与某 catch 匹配则执行该 catch；无论是否异常，finally 都会执行；
  • try 正常完成时 catch 不执行；
  • finally 中写 return 的危害：
    • 覆盖 try / catch 的返回值；
    • 吞掉未处理异常，使调用方无法感知错误；
    • 规范上禁止在 finally 中写 return。

10.（简答）Unity 序列化规则

标准答案：

会被序列化：

  • public 字段；
  • 带 [SerializeField] 的 private / protected 字段；
  • 带 [Serializable] 的自定义 class / struct；
  • 数组、List<T> 等 Unity 支持的集合；
  • Unity 内置类型（int / float / string / bool / Vector3 / Color 等）。

不会被序列化：

  • static / const / readonly 字段；
  • 属性（property）；
  • Dictionary / Stack / Queue 等集合；
  • 未标记 [Serializable] 的自定义类型、未标记 [SerializeReference] 的接口/多态引用；
  • 大部分 System 命名空间下的类型。

[SerializeField] 的作用：让非 public 字段也能被序列化并在 Inspector 中显示，随 Prefab / 场景 / 资源保存与加载。
