一、客观题

C# 基础

1. 值类型变量通常存储在？
A. 托管堆　B. 栈（或作为字段内联在所属对象中）　C. 静态数据区　D. 线程本地存储

  • 正确答案：B
  • 解析：局部值类型在栈上；值类型作为对象字段时内联在堆对象中，不在静态区或线程本地存储。

2. object o = 10; 这行代码发生了什么？
A. 拆箱，把引用类型还原为值类型　B. 隐式引用转换，不产生额外开销　C. 装箱，会在托管堆分配对象　D. 编译错误，值类型不能赋给 object

  • 正确答案：C
  • 解析：值类型 int 转 object 引用类型即装箱，会在托管堆分配；B 的”无额外开销”是常见误选。

3. 关于 string 的说法，正确的是？
A. 每次修改都会生成新的字符串对象　B. string 是值类型，赋值时复制内容　C. string 是可变引用类型　D. == 比较的是两个字符串的引用地址

  • 正确答案：A
  • 解析：string 是引用类型但不可变，修改会生成新对象；== 被重载为值比较。

4. 关于 const 和 readonly，正确的是？
A. readonly 是编译时常量，const 是运行时常量　B. 两者都可以是实例字段　C. const 字段可以在构造函数中赋值　D. const 是编译时常量且隐式 static

  • 正确答案：D
  • 解析：const 编译期确定、隐式 static、不能是实例字段、不能构造赋值；readonly 运行期可赋值一次、可实例字段。

5. 关于 ref 和 out，正确的是？
A. out 参数必须在传入前初始化　B. out 参数必须在方法内赋值　C. ref 参数必须在方法内赋值　D. 两者都不能用于值类型

  • 正确答案：B
  • 解析：ref 传入前必须初始化；out 传入前不用初始化但方法内必须赋值；两者都可用于值类型。

6. 关于接口和抽象类，正确的是？
A. 一个类可以实现多个接口　B. 接口可以包含实例字段　C. 抽象类可以多重继承　D. 接口可以被实例化

  • 正确答案：A
  • 解析：接口不能含实例字段、不能实例化；C# 类只能单继承抽象类。

7. struct 的默认值/默认构造，正确的是？
A. struct 不能声明任何构造函数　B. struct 可以声明析构函数　C. struct 的默认值：各字段为 0 / null　D. struct 可以继承类

  • 正确答案：C
  • 解析：struct 可声明构造函数、无析构函数、不能继承类；默认零初始化。

8. 需要按 key 频繁查找，最适合的数据结构是？
A. List<T>　B. HashSet<T>　C. SortedList<TKey,TValue>　D. Dictionary<TKey,TValue>

  • 正确答案：D
  • 解析：哈希表平均 O(1) 查找；List 为 O(n)。

9. object o = 10; int i = (int)o; 中第二句发生了什么？
A. 无操作，直接复制引用　B. 装箱（值类型 → 引用类型）　C. 编译错误，object 不能强制转换为 int　D. 拆箱（引用类型 → 值类型）

  • 正确答案：D
  • 解析：第一句 object o = 10; 是装箱（值 → 引用）；第二句 int i = (int)o; 是拆箱（引用 → 值）。题目问的是第二句。

10. StringBuilder 相比直接用 string 拼接的优势是？
A. 可变，减少频繁的临时字符串分配　B. 每次拼接都会生成新的字符串对象　C. 线程安全，适合多线程拼接　D. 底层是链表，随机访问更快

  • 正确答案：A
  • 解析：StringBuilder 内部维护可变缓冲，避免大量临时字符串；它不是线程安全的。

11. 关于 static 成员，正确的是？
A. 属于实例，每个对象一份　B. 不能被类外部访问　C. 属于类型，所有实例共享　D. 每次 new 都会复制一份

  • 正确答案：C

12. 关于 virtual 和 abstract，正确的是？
A. virtual 和 abstract 方法必须有实现　B. virtual 有默认实现可被重写，abstract 无实现、必须被子类重写　C. virtual 方法可被重载，abstract 必须被子类重载　D. abstract 类不能包含方法实现

  • 正确答案：B

13. sealed 关键字的作用是？
A. 允许继承，但禁止重写　B. 提高运行性能　C. 必须与 abstract 一起使用　D. 禁止继承（类）或禁止重写（方法）

  • 正确答案：D

14. 关于委托（delegate）与事件（event），正确的是？
A. 事件是对委托的封装，外部只能 += / -=，不能直接调用或赋值　B. 两者完全一样，可以互换　C. 事件不能多播　D. 委托不能用 +=

  • 正确答案：A

15. int? 的本质是？
A. int　B. object　C. Nullable<int>　D. string

  • 正确答案：C

16. 关于泛型约束，正确的是？
A. where T : struct 表示 T 必须是引用类型　B. where T : class 表示 T 必须是值类型　C. where T : new() 表示 T 必须具有公共无参构造函数　D. 泛型类型参数不能添加多个约束

  • 正确答案：C
  • 解析：struct 约束值类型，class 约束引用类型，new() 要求公共无参构造函数；泛型参数可同时添加多个约束。

17. 关于 try / catch / finally，正确的是？
A. finally 只在 try 中发生异常时才执行　B. try 可以单独出现，不需要 catch 或 finally　C. finally 无论 try 是否发生异常（且未被提前终止）都会执行　D. throw 抛出异常后，同一方法的 finally 不会执行

  • 正确答案：C
  • 解析：finally 用于释放资源，正常与异常路径都会执行；try 必须搭配 catch 或 finally。

18. 关于 yield return，正确的是？
A. 每次 MoveNext() 执行到下一个 yield return 并暂停，保存当前状态　B. yield return 会创建新线程执行后续代码　C. yield return 可以放在带 catch 的 try 块中　D. 迭代器方法在调用时会立即执行完整个方法体

  • 正确答案：A
  • 解析：yield 是惰性迭代器，调用 MoveNext 才推进到下一个 yield；C# 禁止 yield return 出现在带 catch 的 try 中。

19. C# 属性（property）的本质是？
A. 属性就是字段，直接访问内存　B. 属性不能包含任何逻辑　C. 自动属性不能有访问修饰符　D. 属性的 get/set 会被编译为 get_/set_ 方法

  • 正确答案：D
  • 解析：属性本质是方法（get_/set_），可包含逻辑，不是字段。

20. 关于 Lambda 表达式与闭包，正确的是？
A. Lambda 不能捕获外部局部变量　B. 捕获的外部局部变量会被提升到编译器生成的闭包类中，可能产生堆分配　C. Lambda 一定是静态方法，不会产生任何分配　D. 闭包捕获的是变量的值，之后外部修改变量不会影响闭包

  • 正确答案：B
  • 解析：闭包会生成显示类（display class）并捕获变量（按引用捕获变量本身），可能带来 GC 分配。

21. 关于 Func<T> 与 Action<T>，正确的是？
A. 两者都有返回值　B. 两者都没有返回值　C. Func 有返回值，Action 无返回值　D. Func 最多只能有一个参数

  • 正确答案：C
  • 解析：Func<..., TResult> 最后一个类型参数为返回值；Action<...> 无返回值。两者都支持多个参数。

22. 关于 using 语句，正确的是？
A. 作用域结束时自动调用 Dispose()，发生异常时也会调用　B. 作用域结束时自动调用 Dispose()，但发生异常时不会调用　C. using 不能与 try 一起使用　D. using 要求类型实现 IComparable

  • 正确答案：A
  • 解析：using 编译为 try/finally，保证 Dispose() 被调用；要求类型实现 IDisposable。

23. 关于 C# 泛型，正确的是？
A. 泛型在运行时总是退化为 object，因此必然发生装箱　B. 泛型不能有多个类型参数　C. 泛型类型参数不能添加约束　D. 泛型可避免值类型的装箱 / 拆箱，提升性能

  • 正确答案：D
  • 解析：泛型为值类型生成专用代码，避免装箱；支持多类型参数与约束。

24. 关于 IEnumerable<T> 与 IEnumerator<T>，正确的是？
A. 两者完全等价，可以互换　B. IEnumerable<T> 提供 GetEnumerator()，IEnumerator<T> 提供 MoveNext() / Current　C. IEnumerator<T> 只能用于 foreach，不能手动调用　D. IEnumerable<T> 提供 MoveNext() / Current

  • 正确答案：B
  • 解析：IEnumerable<T> 是可枚举对象，IEnumerator<T> 是迭代器游标，两者职责不同。

Unity 引擎基础

25. 生命周期函数的正确顺序是？
A. Awake → Start → OnEnable　B. Awake → OnEnable → Start　C. OnEnable → Awake → Start　D. Start → Awake → OnEnable

  • 正确答案：B

26. 物理相关的更新应在哪个函数中进行？
A. Update　B. FixedUpdate　C. LateUpdate　D. OnGUI

  • 正确答案：B
  • 解析：FixedUpdate 按固定物理步长执行，物理计算应放这里。

27. 让移动速度与帧率无关，位移应乘以？
A. Time.time　B. Time.unscaledTime　C. Time.deltaTime　D. Time.fixedDeltaTime

  • 正确答案：C
  • 解析：Update 中乘 deltaTime；FixedUpdate 中物理位移才乘 fixedDeltaTime。

28. 触发器（Trigger）检测需要满足？
A. 双方都必须有 Rigidbody　B. 只要有 Collider 即可　C. 只要有 Rigidbody 即可　D. 至少一方有 Rigidbody（或 CharacterController）且 Collider 勾选 IsTrigger

  • 正确答案：D

29. 关于 Time.timeScale = 0，正确的是？
A. Update 不再被调用　B. WaitForSeconds 仍按真实时间推进　C. Time.deltaTime 变为 0，物理与带缩放的等待暂停，但 Update 仍会调用　D. Time.unscaledTime 也停止推进

  • 正确答案：C
  • 解析：timeScale=0 时 deltaTime 为 0、物理与缩放等待暂停；Update 仍每帧调用，unscaledTime 继续推进。

30. 摄像机平滑跟随目标，通常放在哪个函数？
A. Update　B. LateUpdate　C. FixedUpdate　D. Awake

  • 正确答案：B

31. Destroy(obj) 与 Destroy(obj, 2f) 的区别是？
A. 无区别　B. 后者把对象设为 inactive　C. 前者立即标记为销毁，后者延迟 2 秒标记为销毁　D. 前者立刻销毁，后者延迟 2 秒后立刻销毁

  • 正确答案：C
  • 解析：Destroy(obj, t) 延迟 t 秒销毁；不是 SetActive(false)。

32. 控制两个 Layer 之间是否发生物理碰撞的是？
A. Tag　B. Sorting Layer　C. Layer 本身的编号　D. Physics 的 Layer Collision Matrix

  • 正确答案：D

33. Awake 与 Start 的区别，正确的是？
A. 两者完全一样，只是名字不同　B. Awake 在对象实例化/加载时调用，Start 在第一次 Update 前调用　C. Start 早于 Awake　D. Awake 在每次对象激活时调用一次

  • 正确答案：B

34. OnEnable 的调用时机是？
A. 仅在整场游戏开始时调用一次　B. 每帧调用一次　C. 对象销毁时调用　D. 每次组件/对象被激活或启用时调用

  • 正确答案：D

35. 关于 Invoke 与协程（Coroutine），正确的是？
A. Invoke 只能按延迟调用方法，协程可跨帧、带参数、可暂停/停止，控制更灵活　B. 两者完全相同，可互换　C. Invoke 比协程更灵活　D. 协程启动后不能停止

  • 正确答案：A

36. Instantiate(prefab) 的返回值是？
A. void　B. 克隆出来的对象（GameObject 或 Component）　C. bool　D. Prefab 资源本身

  • 正确答案：B

37. 关于 FindObjectOfType，正确的是？
A. 高效，推荐每帧调用　B. 不影响性能，与直接引用一样　C. 只能查找未激活对象　D. 会遍历场景，性能较差，应缓存结果

  • 正确答案：D

38. UGUI 中决定同一 Canvas 下 UI 元素渲染先后顺序的是？
A. Canvas 层级 + Sorting Layer + Order in Layer　B. Tag　C. Layer　D. 游戏对象名字

  • 正确答案：A

39. Physics.Raycast 的作用是？
A. 检测两个 Collider 是否重叠　B. 获取对象的所有组件　C. 检测射线与碰撞体的相交　D. 计算两点距离

  • 正确答案：C

40. 关于 Unity 序列化，正确的是？
A. public Dictionary<string, int> dict; 会被自动序列化　B. 未加 [SerializeReference] 的接口类型字段可以被序列化　C. [SerializeField] 可以让 private 字段被序列化　D. static 字段也会被序列化

  • 正确答案：C
  • 解析：Unity 不序列化 Dictionary/Stack/Queue、static/const/readonly 与属性；接口/多态引用需 [SerializeReference]；[SerializeField] 可序列化 private 字段。

41. 关于 Animator，正确的是？
A. 只能播放单个 AnimationClip，不能做状态机　B. 参数不支持 Trigger 类型　C. 不需要 Avatar 也能用于人形动画　D. 通过状态机与参数控制动画过渡

  • 正确答案：D
  • 解析：Animator 的核心是状态机与参数；人形动画需要 Avatar。

42. 关于动画事件（Animation Event），正确的是？
A. 只能传递 string 参数　B. 可在动画的特定时间点调用脚本中的方法　C. 只能用代码手动触发，不能在面板添加　D. 无法传递任何参数

  • 正确答案：B
  • 解析：动画事件可在指定帧回调脚本方法，可传 int/float/string/object 等参数。

43. SceneManager.LoadScene("Level1") 默认的加载模式是？
A. 叠加加载，保留当前场景　B. 仅预加载资源，不激活场景　C. 加载完成后替换当前场景（Single）　D. 异步加载且不阻塞主线程

  • 正确答案：C
  • 解析：默认 Single，会卸载当前场景；Additive 为叠加加载。

44. 关于异步加载场景，正确的是？
A. 返回 AsyncOperation，可用 allowSceneActivation 控制激活时机　B. 会阻塞主线程直到加载完成　C. progress 精确到每一帧的加载字节数　D. 异步加载无法获得进度

  • 正确答案：A
  • 解析：异步加载返回 AsyncOperation，可用 progress 显示进度，allowSceneActivation 控制何时切换。

45. Unity 中 Rigidbody 的 Body Type 不包括？
A. Dynamic（动态）　B. Kinematic（运动学）　C. Static（静态）　D. Elastic（弹性）

  • 正确答案：D
  • 解析：Body Type 为 Dynamic / Kinematic / Static，没有 Elastic。

46. Rigidbody 设为 Kinematic 后，正确的是？
A. 完全不受任何碰撞检测影响　B. 不受重力与物理力影响，但可通过 MovePosition/MoveRotation 移动，并参与碰撞检测　C. 与 Static 完全相同　D. 会自动下落

  • 正确答案：B
  • 解析：Kinematic 不受力与重力，需用 MovePosition/MoveRotation 移动，仍参与碰撞检测。

47. 关于 CharacterController 与 Rigidbody，正确的是？
A. 两者完全相同　B. 受物理力驱动　C. 适合角色移动，不依赖物理力，但能处理碰撞与斜坡　D. Rigidbody 不能用于角色控制

二、主观题

1.（简答）Update、FixedUpdate、LateUpdate 的区别与使用场景

参考答案：

三者都是 Unity 帧循环中的回调，区别在于调用时机、时间增量与适用场景：

  • Update：每帧调用一次，频率随帧率变化；用 Time.deltaTime 计算与帧率无关的位移。适合处理输入、UI 刷新、游戏逻辑等。
  • FixedUpdate：按固定时间步长调用（默认 0.02s，即 50Hz），一帧内可能调用 0 次或多次；用 Time.fixedDeltaTime。适合物理计算（Rigidbody、力、碰撞）。
  • LateUpdate：在所有 Update 执行完之后调用，每帧一次。适合相机跟随、跟随逻辑，保证目标在 Update 中更新完毕后再更新相机。

记忆：物理放 FixedUpdate，输入与常规逻辑放 Update，相机跟随放 LateUpdate。

2.（简答）Unity 协程在什么情况下会停止/失效？

参考答案：

  1. GameObject 被 SetActive(false)：协程停止，且重新激活后也不会自动恢复。
  2. GameObject 被 Destroy：协程终止。
  3. 主动调用 StopCoroutine / StopAllCoroutines：按指定或全部停止。
  4. 协程内抛出未捕获异常：协程静默终止，后续代码不再执行（Unity 会打印异常日志）。
  5. 补充边界：MonoBehaviour.enabled = false 不会停止协程；真正使其停止的是 GameObject 失活或被销毁。

5.（简答）值类型 vs 引用类型 + 装箱拆箱

参考答案：

值类型与引用类型的区别：

  • 存储：局部值类型在栈上；值类型作为对象字段时内联在堆对象中。引用类型对象分配在托管堆上，变量保存的是引用。
  • 赋值语义：值类型赋值复制值；引用类型赋值复制引用，两个变量指向同一对象。
  • 继承：值类型不能继承类，但可实现接口；引用类型支持继承与多态。
  • 默认值：值类型默认 0 / false；引用类型默认 null。

装箱与拆箱：

  • 装箱：值类型 → 引用类型（如 object o = 10;），在托管堆分配对象并复制值，有性能开销。
  • 拆箱：引用类型 → 值类型（如 int i = (int)o;），做类型检查后取值，通常不产生堆分配。
  • 值类型转换为 object 或其所实现的接口时会装箱，应避免在高频路径中大量使用。

6.（简答）Awake / Start / OnEnable

参考答案：

  • Awake：对象加载/实例化时调用一次，用于初始化（获取引用、初始化数据）。只要 GameObject 处于激活状态就会调用，与组件 enabled 状态无关。
  • OnEnable：组件/对象每次被启用或激活时调用；与 OnDisable 成对出现，适合做订阅/退订、显示/隐藏等对称逻辑；可多次调用。
  • Start：在第一次 Update 之前调用一次，且仅在组件 enabled 时执行；若初始处于禁用状态，则等启用后才执行。

首次激活时的调用顺序：Awake → OnEnable → Start。

9.（简答）请说明 try / catch / finally 的执行顺序；如果 finally 中写了 return，会发生什么？

参考答案：

  • 执行顺序：先执行 try 块；若 try 中抛出异常且与某个 catch 匹配，则执行该 catch 块；无论是否发生异常，finally 块都会执行（除非进程崩溃、环境退出等极端情况）。
  • try 正常完成时 catch 不执行，直接进入 finally。
  • finally 中写 return 的危害：
    • 会覆盖 try / catch 中的 return 值；
    • 会吞掉 try / catch 中未处理的异常，使调用方无法感知错误；
    • 因此规范编码中禁止在 finally 中写 return。

10.（简答）请说明 Unity 的序列化规则：哪些字段会被序列化？[SerializeField] 有什么作用？哪些常见类型无法被 Unity 直接序列化？

参考答案：

  • 会被序列化：
    • public 字段；
    • 加 [SerializeField] 的 private / protected 字段；
    • 加 [Serializable] 的自定义 class / struct（及其 public 字段）；
    • 数组、List<T> 等 Unity 支持的集合；
    • Unity 内置类型（int / float / string / bool / Vector3 / Color 等）。
  • 不会被序列化：
    • static、const、readonly 字段；
    • 属性（property）；
    • Dictionary、Stack、Queue 等集合；
    • 未加 [Serializable] 的自定义类型，未加 [SerializeReference] 的接口 / 多态引用；
    • 大部分 System 命名空间下的类型（如 DateTime）。
  • [SerializeField] 的作用：让非 public 字段也能被 Unity 序列化，在 Inspector 中显示，并随 Prefab / 场景 / 资源一起保存与加载。
