一、客观题

C# 编码实践

1. 项目中有 2000 个敌人对象，每个都挂着一个脚本，Update 方法体为空但保留了一个未使用的 public 字段。Profiler 中 Scripts 每帧开销约 0.6 ms。以下判断最准确的是？
A. 开销来自 public 字段的序列化，与每帧调用 Update 无关　B. 空 Update 会被 IL2CPP 自动剔除，开销主要来自物理系统　C. 空 Update 只在编辑器下计入，发布包中不会产生这段开销　D. 空 Update 仍会被逐个调用，移除或禁用可省下这部分开销

  • 正确答案：D
  • 解析：空 Update 仍会进入每帧调用流程，单次很小但 2000 个对象会累加；它不会被构建自动剔除，也与字段序列化无关。

2. 线上偶发 NullReferenceException，堆栈只显示在 Update 的某一行，本地无法复现。以下哪种排查方式最可能定位根因？
A. 在 Update 外层统一加 try/catch，先把异常压住避免崩溃　B. 在该行前补充对象来源与生命周期日志，结合堆栈构造最小复现　C. 给该行涉及的多数引用统一加 ?.，从表现上规避空引用　D. 让玩家重启客户端，观察异常是否会在重启后自行消失

  • 正确答案：B
  • 解析：定位空引用要先确认是哪个引用、在什么生命周期为空；try/catch 与 ?. 只会掩盖问题，重启也无法定位根因。

3. 战斗中血条文本每帧刷新，Profiler 中 GC Alloc 约 1.2 KB/帧，Canvas.BuildBatch 也有开销，但数值 1 秒才变化一次。以下哪种改法同时解决 GC 与无效重建？
A. 缓存字符串，仅在数值变化时赋值，并避免每帧拼接　B. 换成 TextMeshPro，用 SDF 降低字形重建的开销　C. 把文本拆到独立 Canvas，缩小网格重建的范围　D. 把刷新移到 FixedUpdate，降低文本更新的频率

  • 正确答案：A
  • 解析：GC 来自每帧拼接字符串，重建来自无意义的重复赋值；只有同时消除两者才完整。B/C 只减少重建，D 仍会分配且频率并不对应变化时机。

4. 一个子弹在 Update 中频繁获取目标对象上的 Enemy 组件，Profiler 中 GetComponent 相关耗时明显，且目标可能在运行中切换。以下处理最合理的是？
A. 继续每帧调用，用对象池复用子弹来摊薄查找开销　B. 缓存当前目标组件，在目标切换或初始化时重新获取　C. 改用 GameObject.Find 按名字查找目标身上的组件　D. 把目标组件提升为静态字段，在第一次获取后长期缓存

  • 正确答案：B
  • 解析：正确做法是缓存引用并只在目标变化时刷新；对象池不能减少每帧查找，Find 更慢，静态字段无法处理多个目标。

5. 需要在碰撞回调中判断对象上是否存在 Enemy 组件，存在才结算伤害，不存在则跳过；该回调每秒可能触发上千次。以下做法最合理的是？
A. 先用 FindObjectOfType 查找一次，再在回调中复用结果　B. 用 GetComponent 并判断返回值是否为 null 后决定处理　C. 用 GetComponentInChildren 连同子对象一起查找后判空　D. 用 TryGetComponent 判断存在性，避免找不到时的额外分配

  • 正确答案：D
  • 解析：TryGetComponent 用 out 返回结果，语义清晰且避免找不到时的分配；GetComponent 判空也可行但会有不必要的查找开销，子对象/全局查找范围更不合适。

6. 子弹与敌人每秒发生大量碰撞，需要在 OnTriggerEnter 中判断对方是否为 Enemy，Profiler 显示每次都有少量 GC Alloc。以下原因与改法最准确的是？
A. GetComponent 产生字符串分配，改用 TryGetComponent 判断　B. name == "Enemy" 产生字符串分配，改用 CompareTag 比较　C. layer 比较产生字符串分配，改用 LayerMask 位运算判断　D. tag == "Enemy" 产生字符串分配，改用 CompareTag 比较

  • 正确答案：D
  • 解析：tag 与字符串字面量直接比较会产生分配，应使用 CompareTag；name 不是 tag，layer 比较是整数不产生分配，GetComponent 与 tag 判断无关。

7. 战斗结算逻辑每帧执行，其中有一句 Debug.Log 拼接字符串。发布版本已关闭日志输出，但 Profiler 仍有 GC Alloc。以下处理最合理的是？
A. 用条件编译或参数化日志，避免发布版本执行字符串拼接　B. 把日志级别改为 LogWarning，降低日志输出的频率　C. 用 try/catch 包住日志，出现异常时跳过本次输出　D. 把 Debug.Log 换成 Debug.LogFormat，减少字符串拼接

  • 正确答案：A
  • 解析：关闭日志输出不等于不执行参数拼接；应让发布版本不进入拼接逻辑。改级别、包 try/catch、LogFormat 都仍会构造或格式化字符串。

8. 一个 UI 面板订阅了全局事件，关闭时只调用了 Destroy(gameObject) 而未退订。之后事件再次触发，控制台报 MissingReferenceException。以下解释最准确的是？
A. 对象销毁后事件会自动清空监听列表，报错来自 GC　B. 事件系统会自动忽略已销毁对象，报错来自其他订阅者　C. 编译时订阅者类型与事件签名不匹配，运行时才暴露　D. 长生命周期事件仍持有已销毁对象的引用，回调访问时出错

  • 正确答案：D
  • 解析：事件委托持有订阅者引用，对象销毁后引用仍在；事件触发时调用已销毁对象的方法就会报 MissingReferenceException。

9. 委托在变量赋值前创建、赋值后调用，控制台输出是？

A. 5　B. 0　C. 编译错误　D. 运行时异常

  • 正确答案：A
  • 解析：闭包捕获的是变量本身而不是创建委托时的值；调用委托时 x 已是 5，因此输出 5。

10. 一个文件解析方法可能抛出 FormatException 和 IOException。调用方希望：可恢复的错误继续处理，不可恢复的错误记录后向上抛出。以下 catch 写法最合理的是？
A. 捕获后静默忽略，保证调用方流程不因异常而中断　B. 用 catch (Exception) 统一捕获，记录日志后返回 null　C. 分别捕获具体异常，可恢复的处理并记录，不可恢复的包装后抛出　D. 只捕获 IOException，让 FormatException 继续向上传播

  • 正确答案：C
  • 解析：应按异常类型区分处理能力，并且不丢栈；统一吞掉、返回 null 或只捕获部分类型都会造成行为不可控或掩盖问题。

11. 玩家在输入框中输入等级数值，可能包含空格、字母或超范围数字。解析失败时要给出明确提示，且不能因为异常影响帧率。以下做法最合适的是？
A. 用 int.Parse 并捕获异常，异常时提示输入非法　B. 先用 int.TryParse 判断，再校验范围并给出对应提示　C. 用 Convert.ToInt32 并捕获异常，兼容更多输入格式　D. 用 float.Parse 解析后取整，避免整数解析失败

  • 正确答案：B
  • 解析：不可信输入应使用 TryParse 避免异常路径；Parse/Convert 在非法输入时会抛异常，float 解析取整会改变语义。

12. 一个 MonoBehaviour 单例在切换场景后再次被访问时抛出 MissingReferenceException。以下原因与修复最准确的组合是？
A. 场景切换会阻止静态构造，应把实例预加载到 Resources　B. 静态字段会被场景切换重置为空，应在 Awake 中重新赋值　C. 单例不能跨场景使用，应把逻辑改成普通静态工具类　D. 对象未跨场景保留被销毁，静态引用变伪空

  • 正确答案：D
  • 解析：MonoBehaviour 单例未跨场景保留时对象被销毁，静态引用变成伪空；应使用 DontDestroyOnLoad 并处理重复实例。

13. 每帧对 300 个敌人执行 Where(...).OrderBy(...).FirstOrDefault() 查找最近目标，Profiler 中 GC Alloc 明显。以下判断最准确的是？
A. 问题在于 LINQ 是反射实现，IL2CPP 下无法编译到原生代码　B. LINQ 链会产生迭代器、委托与排序缓冲；应改为一次遍历手写查找　C. 问题在于 lambda 参数被装箱，与迭代器和排序缓冲无关　D. 只要把 Where 换成 ForEach，就不会再产生多数分配

  • 正确答案：B
  • 解析：LINQ 链式调用会分配迭代器、委托与中间集合，排序还会分配缓冲；热路径应改为一次遍历手写查找。IL2CPP 支持 LINQ，装箱也不是主因。

14. 一帧内要对上千个配置 key 做区分大小写的相等判断，当前使用 ToLower() 后比较，Profiler 有 GC Alloc。以下优化最合理的是？
A. 改用 a.CompareTo(b) == 0，比较过程不会创建新字符串　B. 改用 StringComparison.CurrentCulture，保证多语言下结果正确　C. 改用 StringComparison.Ordinal 直接比较，避免 ToLower 分配　D. 把 key 预先缓存为小写字符串，比较时不再做大小写转换

  • 正确答案：C
  • 解析：key 区分大小写时应使用 Ordinal 直接比较，避免 ToLower 产生的临时字符串；区域性比较与 CompareTo 语义不同，缓存小写会丢失大小写差异。

15. 一个玩家数据类需要在 Inspector 中配置、运行时只读，并在赋值时做范围校验。以下字段/属性设计最合适的是？
A. 使用自动属性 get; set;，另写一个校验方法在外部调用　B. 使用 public 字段，简单直接且方便在 Inspector 中配置　C. 私有字段加 SerializeField　D. 使用 static 字段，保证全局唯一并方便在多数位置访问

  • 正确答案：C
  • 解析：SerializeField 让私有字段可在 Inspector 配置，只读属性对外暴露并在 set 中校验，兼顾封装与校验；public 字段与自动属性都无法强制校验。

16. 一个下载任务需要返回结果、传播异常并支持取消，调用方还要在完成后更新 UI。以下选择最合适的是？
A. 用 InvokeRepeating 轮询下载状态，完成后更新 UI　B. 用协程包装下载，通过全局变量传递结果与异常并更新 UI　C. 用 async/await 配合 Task 或 UniTask 更新 UI　D. 直接用 Thread 执行下载，并在子线程中更新 UI

  • 正确答案：C
  • 解析：需要返回值、异常传播与取消时 async/await 更合适，但更新 UI 必须回到主线程；协程难以传播返回值与异常，轮询浪费，子线程更新 UI 不安全。

17. 一个对象池需要同时存放 int、Vector3 和自定义 class 实例。以下设计最容易引入装箱的是？
A. 用 object 或非泛型接口作为池的元素类型　B. 用泛型 ObjectPool<T> 分别为不同类型实例化　C. 用结构体数组按类型分桶存储不同元素　D. 用 ScriptableObject 保存对象池的配置数据

  • 正确答案：A
  • 解析：object 与非泛型接口存放值类型会发生装箱；泛型池与按类型分桶都不会装箱，ScriptableObject 只用于配置。

18. 一份资源路径需要运行时从 StreamingAssets 读取后确定，读取完成后不应再被修改。以下定义最合适的是？
A. 用 const 常量，在编译期确定并内联到多数调用方　B. 用 static readonly 字段　C. 用 public static 可变字段，运行时按读取结果赋值　D. 用普通实例字段，每个对象各自保存一份路径副本

  • 正确答案：B
  • 解析：运行时才能确定的值不能用 const；static readonly 可以在运行时初始化且之后不可再赋值。public static 可变字段与实例字段都无法保证不被修改。

19. 发布版本需要保留错误与警告、过滤普通调试日志，同时避免日志本身产生字符串分配。以下做法最合理的是？
A. 用 try/catch 包住日志，出现异常时跳过本次输出　B. 全部使用 LogError，保证多数信息都能在线上被看到　C. 发布版本全部关闭日志，只在崩溃时打印异常堆栈　D. 用条件编译或按级别封装日志

  • 正确答案：D
  • 解析：应按级别过滤并避免发布版本执行拼接；全部用 LogError 会淹没关键信息，全部关闭会丢失警告，try/catch 不能减少字符串分配。

20. 动画状态名分散在多个脚本中硬编码，最近一次改名导致多处运行时找不到状态。以下改法最能避免再次出错的是？
A. 在 Awake 中缓存多数状态名，出错时打印日志排查　B. 用数字索引替代字符串状态名，运行时效率更高　C. 用拼音简写代替英文状态名，降低拼写错误概率　D. 用 nameof 或常量集中定义状态名，改名时编译期报错

  • 正确答案：D
  • 解析：nameof 或常量能在编译期发现改名遗漏；数字索引和拼音仍靠人工对应，运行时报错也无法阻止问题上线，缓存只是改善排查。

Unity 工程实践

21. 场景中大量对象需要引用同一个管理器，团队有人每帧用 GameObject.Find 查找。以下改造最合理的是？
A. 改用 tag 查找，比按名字查找更快　B. 在 Update 中继续查找，用对象池降低查找频率　C. 初始化时通过 Inspector 注入或单例获取并缓存引用　D. 把管理器设为静态类，避免查找对象

  • 正确答案：C
  • 解析：引用应在初始化阶段注入并缓存；对象池不能减少每帧查找，tag 查找同样有开销，静态类无法持有场景对象。

22. 一个脚本在 Awake 中访问另一个对象的组件，偶发为空；两个对象都在同一场景中激活。以下调整最合理的是？
A. 在 Update 中每帧重试，直到引用可用　B. 全部初始化都放在 Awake，尽量越早越好　C. 把依赖其他对象的初始化移到 Start，或显式控制执行顺序　D. 把依赖对象设为 DontDestroyOnLoad，保证先创建

  • 正确答案：C
  • 解析：Awake 的执行顺序并不保证，跨对象依赖应放到 Start 或通过 Script Execution Order/显式流程控制；逐帧重试与 DontDestroyOnLoad 都不是正解。

23. 三个管理器需要在初始化时按 A→B→C 顺序执行，且不能修改它们的代码。以下做法最可靠的是？

资源与热更

68. 一个大型项目把所有资源打成一个 AB，更新一张小图也要下载整个包。以下分包方案最合适的是？
A. 每个资源单独一个 AB，把更新粒度做到最小　B. 按模块与公共依赖分包，控制包大小并避免循环依赖　C. 按资源类型分包，纹理、模型、音频各自成一个包　D. 保持单包不变，只对下载过程做压缩优化

  • 正确答案：B
  • 解析：按模块与公共依赖分包能平衡加载、更新与内存；粒度过细会造成包数量与依赖管理成本，按类型分组会把不同生命周期资源绑在一起。

69. 界面 A 与界面 B 同时引用同一张贴图，A 关闭后 B 仍在显示，但有人直接释放了贴图导致 B 变白。以下机制最合适的是？

  • 正确答案：C
  • 解析：引用计数能保证仍被使用的资源不被提前释放；独立副本浪费内存，全部常驻会持续增长，周期性清理无法解决引用关系。

70. 战斗场景切回主城后，战斗资源没有释放，内存持续上涨。以下卸载时机与做法最合适的是？

  • 正确答案：B
  • 解析：卸载应结合生命周期与引用计数，在切场景等合适时机批量执行；每帧卸载会造成抖动，立即全卸会导致主城资源重复加载。

71. 两个 AB 都引用了同一材质，运行时分别加载后内存中出现两份材质。以下处理最合适的是？

  • 解析：公共资源独立成依赖包可避免重复打包与内存翻倍；各自包含会造成冗余，Resources 不利管理，只保留一份又无法保证引用正确。

73. 客户端与服务端资源版本不一致时，出现协议与资源不匹配的崩溃。以下机制最合适的是？
A. 让玩家手动选择是否更新到最新资源，尊重玩家　B. 每次启动强制全量更新到服务器最新版本，保证一致　C. 只比较资源文件数量，不校验内容以节省时间　D. 版本号、清单与哈希校验，并支持灰度回滚

性能调优

80. 场景静态建筑多、材质变体多、DrawCall 约 800，美术要求保持材质表现且不允许合图。以下优化最可能真正减少 DrawCall 的是？
A. 调整相机 Culling Mask，只渲染主建筑　B. 开启 GPU Instancing，把不同网格合并提交　C. 降低阴影距离与纹理分辨率，减少渲染量　D. 开启 Static Batching

  • 正确答案：D
  • 解析：静态合批不需要合图即可合并静态网格，减少材质变体可进一步降低批次；GPU Instancing 要求相同网格，降画质与 Culling Mask 不减少实际绘制调用。

81. 战斗每帧产生约 3KB GC Alloc，偶发卡顿。以下排查与优化顺序最合适的是？
A. 直接增大堆内存，让 GC 触发的次数变少　B. 用 Profiler 定位分配来源，再消除装箱与闭包　C. 每帧手动调用 GC.Collect，把分配及时清理掉　D. 关闭 GC，避免回收过程造成帧率卡顿并保持流畅

  • 正确答案：B
  • 解析：先定位分配来源再优化才有效；增大堆内存只是延后回收，手动 Collect 会造成更大卡顿，关闭 GC 不可行。

82. 子弹频繁创建销毁，Profiler 中 Instantiate/Destroy 与 GC 都很高。以下实现最合适的是？
A. 用对象池复用子弹，取出与归还时重置对象状态　B. 预先在场景中摆放大量子弹对象，循环使用　C. 每次创建子弹时用 Resources.Load 加载 Prefab　D. 减少子弹数量，避免频繁创建与销毁

  • 正确答案：A
  • 解析：对象池复用能同时降低 Instantiate/Destroy 的 CPU 与 GC；预摆放无法动态取用，Resources.Load 更慢，减少数量改变玩法。

83. 场景中相同材质的物体没有合批，Profiler 显示每个物体一个批次。以下最可能的原因与改法是？
A. 中间插入不同材质/图集或顶点超限，应调整顺序　B. 对象数量太少，达不到合批所需的最小数量，无法触发　C. 分辨率太高，导致渲染批次被拆散，合批失效　D. 需要关闭相机剔除，合批才会重新生效并保持状态连续

  • 正确答案：A
  • 解析：合批要求状态连续且满足顶点/缩放限制；数量、分辨率与相机剔除都不是合批失败的原因。

84. UI 打开后 GPU 填充率很高，Scene 视图 Overdraw 大面积红色。以下优化最合适的是？
