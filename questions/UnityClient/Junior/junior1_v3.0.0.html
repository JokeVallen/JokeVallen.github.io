一、客观题

C# 基础

1. 关于值类型与引用类型的赋值语义，下列说法正确的是？
A. 值类型赋值复制整个值；引用类型赋值复制引用　B. 值类型一定分配在栈上，引用类型一定分配在托管堆上　C. struct 是引用类型，class 是值类型　D. 引用类型赋值会执行深拷贝

  • 正确答案：A
  • 解析：值类型赋值按值复制；引用类型赋值只复制引用，两个变量指向同一对象。值类型作为字段时会内联在堆对象中，因此「值类型一定在栈上」是常见误区。

2. 执行 object o = 10; int n = (int)o; 的过程中，装箱与拆箱各发生几次？
A. 两次装箱、一次拆箱　B. 一次装箱、一次拆箱　C. 一次装箱、零次拆箱　D. 零次装箱、一次拆箱

  • 正确答案：B
  • 解析：int 赋给 object 发生一次装箱；(int)o 把堆上的对象还原为值类型发生一次拆箱。

3. 以下代码的输出是？

A. True，字面量拼接在编译期完成，结果被驻留　B. False，+ 在运行时一定产生新对象　C. True，ReferenceEquals 被重写成了值比较　D. 编译错误

  • 正确答案：A
  • 解析："a" + "b" 两个编译期常量会在编译期折叠为 "ab"，与 a 指向同一驻留字符串，因此 ReferenceEquals 返回 True。若 b 由运行时变量拼接，则会返回 False。

4. 在循环中对字符串做大量拼接时，推荐使用 StringBuilder 的主要原因是？
A. StringBuilder 内部使用不可变字符串，线程更安全　B. StringBuilder 会自动压缩结果字符串　C. 避免每次拼接都产生新的字符串对象，减少 GC　D. StringBuilder 的 == 比较更高效

  • 正确答案：C
  • 解析：string 不可变，普通 + 每次都产生新对象；StringBuilder 在可变缓冲区上追加，显著减少临时对象与 GC。

5. 关于泛型约束，以下说法正确的是？
① where T : class 约束后可以直接使用 new T()
② new() 约束必须放在约束列表的最后
③ where T : struct 允许 T 为可空值类型 int?
④ 一个类型参数可以同时指定多个接口约束

A. ②④　B. ①③　C. ①②　D. ③④

  • 正确答案：A
  • 解析：class 只约束引用类型，不能保证存在无参构造，① 错；new() 必须最后，② 对；struct 约束排除 Nullable<T>（即 int?），③ 错；可同时约束多个接口，④ 对。

6. 关于 try / catch / finally，以下说法正确的是？
① finally 在 try 中执行 return 后仍会执行
② catch 可以不带任何参数直接捕获所有异常
③ finally 中写 return 会覆盖 try 的返回值，应避免
④ 即使 try 中抛出异常，finally 也会执行

A. ①③④　B. ①②④　C. ②③④　D. ①③

  • 正确答案：A
  • 解析：finally 无论正常结束、return 还是异常都会执行，①④ 对；C# 的 catch 必须带异常类型或参数，② 错；finally 中 return 会覆盖原返回值，③ 对。

7. 需要频繁按 key 查找、key 数量大且对顺序无要求时，最合适的集合是？
A. List<T> 配合 IndexOf　B. Queue<T>　C. LinkedList<T>　D. Dictionary<K,V>

  • 正确答案：D
  • 解析：Dictionary 基于哈希表，按 key 查找平均 O(1)；List.IndexOf 是 O(n)，Queue/LinkedList 不适合按键查找。

8. 关于 struct，下列说法正确的是？
A. 一个 struct 可以继承另一个 struct　B. struct 一定比 class 性能更好　C. struct 是引用类型，赋值时复制引用　D. struct 可以有自定义的带参构造函数

  • 正确答案：D
  • 解析：struct 可以有带参构造函数，但不能继承 struct（只能实现接口）；它是值类型，赋值复制整个值；是否更快取决于装箱、复制大小等场景，不能一概而论。

9. 关于 C# 的 event 关键字，以下说法正确的是？
① 事件本质是对委托字段的封装，外部只能 += / -=
② 事件可以在声明它的类外部直接调用 Invoke
③ 一个事件可以被多个方法订阅
④ 声明事件后无需退订，不会造成内存泄漏

A. ②④　B. ①③　C. ①②　D. ③④

  • 正确答案：B
  • 解析：事件对外只暴露订阅/退订，触发只能在声明类型内部，① 对 ② 错；一个事件可被多个方法订阅，③ 对；长期订阅且未退订会导致对象无法回收，④ 错。

10. 关于 for 与 foreach 循环中闭包捕获循环变量的行为，正确的是？
A. for 和 foreach 中闭包都捕获同一个变量　B. for 中每次迭代捕获独立变量，foreach 中共享同一个变量　C. for 中闭包共享同一个变量　D. 两者都会在编译时报错

  • 正确答案：C
  • 解析：for 的循环变量只有一个，闭包共享，常出现 3 3 3；foreach 从 C# 5 起每次迭代使用独立变量，闭包会得到 0 1 2。

11. 关于 using 语句，下列说法正确的是？
A. using 只能用于 IDisposable，且必须搭配 try/catch　B. using 声明离开作用域时调用 Dispose，但发生异常时不会　C. using 保证离开作用域时调用 Dispose，发生异常时也会　D. using 只能用于文件流，不能用于自定义类型

  • 正确答案：C
  • 解析：using 编译为 try/finally，保证 Dispose 一定被调用；任何实现 IDisposable 的类型都可使用，不限于文件流。

12. 以下代码的输出是？

A. -1　B. 抛出 NullReferenceException　C. 0　D. 编译错误

  • 正确答案：A
  • 解析：s?.Length 在 s 为 null 时返回 int? 类型的 null，?? -1 于是输出 -1，不会抛异常。

13. 关于属性 public int HP { get; private set; }，说法正确的是？
A. 外部可以读取和写入 HP　B. 外部只能读取，声明类型内部也不能写入　C. 外部只能读取，声明类型内部可以写入　D. 它等价于公共字段，没有封装意义

  • 正确答案：C
  • 解析：private set 表示只有声明类型内部能赋值，外部只读；相比公共字段仍保留了封装与后续扩展能力。

14. 关于抽象类与接口，以下说法正确的是？
① 一个类只能实现一个接口
② 抽象类可以有字段和构造函数
③ 接口侧重行为契约，C# 8 起也可以有默认实现
④ 抽象类不能有构造函数

A. ①②　B. ③④　C. ②③　D. ①④

  • 正确答案：C
  • 解析：一个类可实现多个接口，① 错；抽象类可含字段、构造函数与实现，② 对 ④ 错；接口侧重契约，C# 8 起支持默认实现，③ 对。

15. 关于 ref 与 out 参数，下列说法正确的是？
A. out 参数在传入前必须先初始化　B. ref 与 out 都必须在方法内重新赋值　C. 二者都不能用于值类型　D. ref 传入前必须初始化

  • 正确答案：D
  • 解析：ref 要求调用前已初始化，方法内可不赋值；out 调用前无需初始化，但方法返回前必须赋值。二者都可用于值类型。

16. 关于 const 与 static readonly，下列说法正确的是？
A. 二者都在运行时初始化　B. const 可以是任意引用类型　C. static readonly 在编译期确定值并内联到调用方　D. const 在编译期确定并内联

  • 正确答案：D
  • 解析：const 编译期常量，会被内联，修改后需要重新编译依赖方；static readonly 运行时初始化，引用类型只能用它而不能用 const。

17. 遍历 List<T> 的同时调用 Remove 会怎样？
A. 正常删除元素并继续遍历，不中断　B. 自动跳过被删除元素，不报错　C. 抛出 InvalidOperationException　D. 编译错误，编译器会拒绝编译

  • 正确答案：C
  • 解析：List 的枚举器带版本号校验，遍历中修改集合会抛出 InvalidOperationException；应改用 for 倒序或先收集再删除。

18. 判断两个字符串内容是否相等，较推荐的做法是？
A. string.Equals(a, b, StringComparison.Ordinal)　B. ReferenceEquals(a, b)，比较引用地址　C. 比较两者的 GetHashCode()，哈希相同即相等　D. a.CompareTo(b) == 0，按区域性规则比较

  • 正确答案：A
  • 解析：Ordinal 按字节序比较，语义明确且无区域性开销；ReferenceEquals 比较引用；哈希相等不代表内容相等；CompareTo 受当前区域性影响。

19. 使用 List<int> 相比非泛型 ArrayList 的主要优势是？
A. List<int> 的内存占用一定更小　B. ArrayList 支持更多类型　C. 避免值类型的装箱拆箱，类型安全且性能更好　D. List<int> 能自动排序

  • 正确答案：C
  • 解析：ArrayList 以 object 存储，存取 int 会装箱拆箱；List<int> 是强类型，避免装箱并提供编译期类型检查。

20. 在 Unity 中，关于 Task、Thread 与协程，下列说法正确的是？
A. Task.Run 中的代码运行在 Unity 主线程，可直接调用 Unity API　B. 协程运行在主线程、适合帧时序；Task/Thread 可跑后台计算　C. Thread 可以安全地操作 Transform　D. async/await 一定比协程性能更好

  • 正确答案：B
  • 解析：Unity API 大多只能在主线程调用；协程在主线程分帧执行，适合表现与时序；后台线程计算完成后需切回主线程再操作 Unity 对象。

21. 关于 yield 与迭代器，下列说法正确的是？
A. yield 方法在调用时会立即执行完整个方法体　B. yield return 只能返回 null　C. 迭代器不能用于 foreach　D. 调用时不会立即执行

  • 正确答案：D
  • 解析：迭代器是延迟执行的状态机，调用方法只拿到 IEnumerator，每次 MoveNext 执行到下一个 yield；foreach 正是基于该协议。

22. 表达式 a ??= b; 的语义是？
A. 若 a 不为 null，则把 b 赋给 a　B. 若 b 不为 null，则把 a 赋给 b　C. 若 a 为 null，则把 b 赋给 a　D. 总是把 b 赋给 a

  • 正确答案：C
  • 解析：??= 是空合并赋值：仅当左值为 null 时才用右值赋值，否则保持原值。

23. 调用 void Foo(params int[] arr) 时传入 Foo(1, 2, 3)，会发生什么？
A. 不会分配数组　B. 编译错误，params 只能传数组　C. 每次调用都会分配一个 int[]　D. 会把每个 int 装箱

  • 正确答案：C
  • 解析：params 本质是数组参数，编译器会把实参收集成新数组；在热路径中高频调用会产生可观的堆分配。已有数组时应直接传数组。

24. 关于 lock，以下说法正确的是？
① lock 锁定的是对象
② lock 的锁对象可以是 null
③ 应避免 lock(this) 或 lock 公共对象，防止外部死锁
④ lock 可以跨进程生效

A. ①②　B. ③④　C. ①④　D. ①③

  • 正确答案：D
  • 解析：lock 锁定的是对象，① 对；锁对象为 null 会抛异常，② 错；使用 this 或公共对象可能被外部同时锁定，应改用私有只读对象，③ 对；lock 仅进程内有效，④ 错。

Unity 引擎基础

25. 一个处于激活状态的 GameObject 上，脚本回调的执行顺序正确的是？
A. Awake → Start → OnEnable　B. Awake → OnEnable → Start　C. Start → Awake → OnEnable　D. OnEnable → Awake → Start

  • 正确答案：B
  • 解析：对象激活时先 Awake，随后 OnEnable，首个 Update 前调用 Start。被 SetActive(true) 重新激活的对象不会再执行 Awake，但会再次执行 OnEnable。

26. 调用 Destroy(gameObject) 后，OnDisable 与 OnDestroy 的调用情况是？
A. 只调用 OnDestroy　B. 只调用 OnDisable　C. 先 OnDestroy 再 OnDisable　D. 先 OnDisable 再 OnDestroy

  • 正确答案：D
  • 解析：对象被销毁前会先触发 OnDisable，随后才触发 OnDestroy。若对象本就处于未激活状态，则不会重复触发 OnDisable。

27. 关于 FixedUpdate，下列说法正确的是？
A. 按固定时间步调用　B. 每渲染帧固定调用一次　C. 其中适合处理输入检测和相机跟随　D. 场景中对象越多调用频率越高

  • 正确答案：A
  • 解析：FixedUpdate 按固定时间步驱动物理；其内 Time.deltaTime 返回固定步长。输入与相机跟随更适合放在 Update / LateUpdate。

28. 在 Update 中，Time.deltaTime 表示？
A. 固定的 0.02 秒物理步长　B. 自游戏开始累计的总时间　C. 上一帧到当前帧的时间间隔　D. 物理系统的固定步长

  • 正确答案：C
  • 解析：Time.deltaTime 是当前帧耗时，随设备与负载变化；受 timeScale 缩放。固定步长用 Time.fixedDeltaTime，总时间用 Time.time。

29. 关于协程 StartCoroutine，下列说法正确的是？
A. 协程运行在独立线程上　B. 禁用脚本组件不会自动停止协程　C. 协程内不能使用 yield return null　D. Time.timeScale = 0 时所有协程一律停止

  • 正确答案：B
  • 解析：协程运行在主线程；禁用组件不会停止协程，但对象被禁用/销毁或调用 StopCoroutine 会停止（WaitForSeconds 受 timeScale 影响，WaitForSecondsRealtime 不受）。

30. 当 Time.timeScale = 0 时，以下哪个等待仍会继续推进？
A. WaitForSeconds　B. WaitForSecondsRealtime　C. WaitForEndOfFrame　D. WaitForFixedUpdate

  • 正确答案：B
  • 解析：WaitForSeconds 使用受缩放的时间，暂停时无法结束；WaitForSecondsRealtime 使用真实时间，暂停时仍可计时。

31. 在 Update 中调用 Destroy(obj)，obj 实际在何时被销毁？
A. 立即销毁　B. 当前帧 Update 之后、渲染之前（通常在帧末）被销毁　C. 下一帧所有 Awake 之前　D. 只有调用 Resources.UnloadUnusedAssets 后才销毁

  • 正确答案：B
  • 解析：Destroy 是延迟销毁，在本帧渲染结束后执行真正的销毁，因此当前帧剩余逻辑仍可访问该对象；需要立即销毁用 DestroyImmediate（仅建议编辑器下使用）。

32. 设置 child.SetParent(parent, false) 时，第二个参数 false 的作用是？
A. 不建立父子关系　B. 不激活子对象　C. 保持子对象的世界坐标不变　D. 不复制父对象的缩放

  • 正确答案：C
  • 解析：worldPositionStays 为 false 时，子对象保留原 localPosition/localRotation/localScale，因此世界坐标会因父级变化而改变；为 true 时会反算以维持世界坐标。

33. transform.position 与 transform.localPosition 的区别是？
A. position 是世界坐标　B. 二者永远相同　C. position 相对父对象，localPosition 是世界坐标　D. localPosition 只读

  • 正确答案：A
  • 解析：position 是世界空间坐标，localPosition 相对父级。父级有位移/旋转/缩放时二者不等价，且 localPosition 可读写。

34. 一个带 Rigidbody 的对象与一个 isTrigger = true 的碰撞体相互进入时，正确的回调是？
A. OnCollisionEnter　B. OnTriggerEnter　C. OnCollisionStay　D. 不会触发任何回调

  • 正确答案：B

标准答案：

标准答案：

  • 执行顺序：先执行 try；若发生异常且与某 catch 匹配则执行该 catch；无论是否异常，finally 都会执行；
  • try 正常完成时 catch 不执行；
  • finally 中写 return 的危害：
    • 覆盖 try / catch 的返回值；

    • 规范上禁止在 finally 中写 return。

10.（简答）Unity 序列化规则

题目： 请列举 Unity 默认会序列化与不会序列化的字段类型；说明 [SerializeField] 的作用，以及 public 字段、static 字段、readonly 字段各自的序列化情况。可补充说明「Inspector 中看不到引用」的常见原因。

标准答案：

会被序列化：

  • public 字段；
  • 带 [SerializeField] 的 private / protected 字段；
  • 带 [Serializable] 的自定义 class / struct；
  • 数组、List<T> 等 Unity 支持的集合；
  • Unity 内置类型（int / float / string / bool / Vector3 / Color 等）。

不会被序列化：

  • static / const / readonly 字段；
  • 属性（property）；
  • Dictionary / Stack / Queue 等集合；
  • 未标记 [Serializable] 的自定义类型、未标记 [SerializeReference] 的接口/多态引用；
  • 大部分 System 命名空间下的类型。

[SerializeField] 的作用：让非 public 字段也能被序列化并在 Inspector 中显示，随 Prefab / 场景 / 资源保存与加载。
