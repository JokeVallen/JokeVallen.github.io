C# 编码实践

1. 在 Update 中保留空函数的主要影响是？
A. 会编译报错　B. 会提高帧率　C. 每帧仍有调用开销，应删除空函数　D. 没有任何影响

  • 正确答案：C
  • 解析：每帧仍有调用开销，应删除空函数

2. 排查 NullReferenceException 时，第一步最合适的做法是？
A. 根据堆栈定位到具体行，确认哪个引用为空　B. 直接加 try/catch 吞掉异常　C. 重启 Unity　D. 删除报错的代码

  • 正确答案：A
  • 解析：根据堆栈定位到具体行，确认哪个引用为空

3. 高频更新的 UI 文本，较推荐的做法是？
A. 每帧都 SetText　B. 用 Debug.Log 代替　C. 仅在数值变化时更新，避免每帧 SetText　D. 每帧销毁重建文本

  • 正确答案：C
  • 解析：仅在数值变化时更新，避免每帧 SetText

4. 在 Update 中频繁调用 GetComponent 的问题与推荐做法是？
A. 没有开销，可随意调用　B. 应每帧调用以刷新　C. 应改用 Find　D. 开销较大，应在 Awake/Start 缓存引用

  • 正确答案：D
  • 解析：开销较大，应在 Awake/Start 缓存引用

5. TryGetComponent 相比 GetComponent 的优势是？
A. 避免找不到组件时的 GC 分配　B. 速度更快但会分配　C. 可以查找未激活对象　D. 会自动创建组件

  • 正确答案：A
  • 解析：避免找不到组件时的 GC 分配

6. 判断对象 Tag 时较推荐使用？
A. tag == “Enemy”　B. name == “Enemy”　C. CompareTag，避免字符串比较分配　D. layer == “Enemy”

  • 正确答案：C
  • 解析：CompareTag，避免字符串比较分配

7. 日志拼接在热路径中的推荐做法是？
A. 直接字符串拼接　B. 每帧打印　C. 使用条件编译或参数化日志，避免临时字符串分配　D. 用 Debug.LogError 代替

  • 正确答案：C
  • 解析：使用条件编译或参数化日志，避免临时字符串分配

8. 事件订阅忘记退订最可能导致？

  • 正确答案：C
  • 解析：对象无法被回收，回调到已销毁对象

9. 在循环中注册闭包捕获循环变量，可能的问题是？
A. 所有闭包捕获同一个变量，最终结果不符合预期　B. 编译错误　C. 循环无法执行　D. 没有影响

  • 正确答案：A
  • 解析：所有闭包捕获同一个变量，最终结果不符合预期

10. 异常处理中 catch 块的推荐做法是？

  • 正确答案：B
  • 解析：至少记录日志，不要静默吞掉异常

  2. 定位：看日志/堆栈、断点、二分法缩小范围，必要时用 Profiler；
  3. 修复：定位根因，最小改动修复；
  4. 验证：本地验证 + 相关用例回归；
  5. 回归：补充测试或用例，避免再次出现，并记录到文档/博客。

2.（简答）你如何设计和管理一个 Unity 项目的目录结构？

参考答案：

按职责分层，例如：

  • Assets/Scripts（按模块划分：UI、Gameplay、Network、Editor…）；
  • Assets/Art（纹理、模型、动画、特效）；
  • Assets/Resources 慎用，尽量用 AssetBundle/Addressables；
  • Assets/Scenes、Assets/Prefabs、Assets/ScriptableObjects；
  • 第三方插件放 Assets/Plugins 或 ThirdParty。
    原则：约定统一、层级清晰、便于查找与打包。

3.（简答）你如何做 UI 弹窗管理与层级规范？请给出关键设计。

参考答案：

  • 统一 UIManager：负责打开/关闭、层级、缓存与并发控制；
  • 弹窗用栈管理，支持返回键逐层关闭；
  • 按类型划分 Sorting Order（背景/主界面/弹窗/Toast/引导）；
  • 打开时遮罩防穿透，关闭时释放或缓存；
  • 层级规范写入文档，配合工具检查。

4.（简答）多人协作中 Prefab/Scene 冲突如何避免与解决？

参考答案：

  • 开启 Force Text 序列化，便于 diff/merge；
  • 拆分 Prefab/场景，减少多人同时修改同一文件；
  • 约定修改区域与提交频率，小步提交；
  • 使用 git mergetool/UnityYAMLMerge 合并；
  • 冲突严重时以一方为基础重建，避免强行覆盖。

5.（简答）你如何设计资源分包与热更新流程？

参考答案：

  • 分包：按模块 + 公共依赖分包，公共资源抽公共包，避免冗余；
  • 版本：清单文件记录版本与哈希；
  • 更新：拉清单 → 比对差异 → 下载 → 校验 → 应用；
  • 加载：引用计数，加载/Release 成对，归零后卸载；
  • 回滚：保留上一版本，异常时切回。

6.（简答）你如何定位并优化一个掉帧问题？请给出步骤。

参考答案：

  1. 用 Profiler 抓取掉帧帧，区分 CPU/GPU 瓶颈；
  2. CPU：看脚本耗时、GC、DrawCall、物理、动画；
  3. GPU：看 Overdraw、SetPass、三角形、纹理带宽；
  4. 针对性优化（合批、对象池、降分辨率、减少 AO/阴影等）；
  5. 真机复测对比，确认收益且未引入新问题。

7.（简答）你如何管理事件订阅与生命周期，避免内存泄漏？

参考答案：

  • 订阅与退订成对，在 OnEnable/OnDisable 或 OnDestroy 中处理；
  • 使用弱引用或事件中心统一管理；
  • 避免匿名闭包长期持有对象；
  • 事件触发前检查监听者有效性；
  • 用 Memory Profiler/工具定期排查泄漏。

8.（简答）你如何做移动端多分辨率与刘海屏适配？

参考答案：

  • 用 Canvas Scaler 按参考分辨率缩放；
  • 关键 UI 用锚点与安全区（Screen.safeArea）；
  • 区分横竖屏，测试主流分辨率；
  • 背景做溢出裁切，避免黑边；
  • 建立适配规范与自测清单。

9.（简答）你如何用 Git 进行多人协作（分支、提交、Code Review）？

参考答案：

  • 分支：主干 + 功能分支 + 发布分支，功能完成即合并；
  • 提交：小步、单一职责、写清说明并关联需求号；
  • 同步：频繁 pull/rebase，减少冲突；
  • Code Review：提交 MR，至少一人评审；
  • 忽略 Unity 的 Library/Temp 等，使用 Force Text 序列化。

10.（简答）你如何设计一个通用无限列表组件？

参考答案：

  • 只创建可见区域 + 缓冲区的 Item，滚动时复用；
  • Item 与数据分离，通过 SetData 刷新；
  • 支持不同 Item 高度时用布局计算偏移；
  • 配合对象池减少 GC；
  • 处理滚动到边界的加载与复用回收。

11.（简答）你如何做版本发布、灰度与回滚？

参考答案：

  • 版本号与构建号规范，发布包与热更包分离；
  • 先内测/小流量灰度，监控崩溃率、留存与关键指标；
  • 出问题可停用热更或回滚到上一版本；
  • 保留发布记录与变更说明，便于追溯。
