题卷版本：v1.0.0

本卷共 30 道客观题 + 5 道主观题，聚焦资源加载、依赖、卸载与热更新。

建议： 做完后把不熟的题补成知识卡片，尤其是引用计数、依赖与版本管理。

一、客观题

1. Addressables 相比直接使用 AssetBundle 的主要优势是？
A. 完全不需要打包　B. 在 AB 之上提供 Catalog、异步加载与引用计数　C. 自动压缩所有纹理　D. 只能用于 Editor

  • 正确答案：B
  • 解析：Addressables 封装了 AssetBundle 的依赖、Catalog、异步加载、远程更新和引用计数，业务层不必自己维护底层包关系。

2. 释放 Addressables 资源句柄应使用？
A. Destroy(handle)　B. GC.Collect()　C. Resources.UnloadUnusedAssets()　D. Addressables.Release(handle)

  • 正确答案：D
  • 解析：Release 会减少引用计数，计数归零后资源才可能被卸载。

3. 通过 Addressables.InstantiateAsync 创建的实例应如何释放？
A. Addressables.ReleaseInstance(go)　B. 只 Destroy(go)　C. 只 Release(handle) 就足够　D. 不需要释放

  • 正确答案：A
  • 解析：实例需要 ReleaseInstance 才能正确归还实例与引用计数；只 Destroy 可能留下计数。

4. 获取一个 AssetBundle 的所有依赖包应使用？
A. AssetBundle.LoadFromFile　B. AssetBundle.Unload(false)　C. AssetBundleManifest.GetAllDependencies　D. Resources.LoadAll

  • 正确答案：C
  • 解析：构建时生成的 Manifest 记录依赖关系，加载资源前必须先把依赖包加载好。

5. AssetBundle 调用 Unload(true) 的风险是？
A. 一定安全　B. 可能卸载正在使用的资源　C. 只卸载依赖　D. 不释放内存

  • 正确答案：B
  • 解析：Unload(true) 会销毁已加载的 Asset 对象，仍在场景中使用的资源会变成 Missing。

6. AssetBundle 资源冗余的常见原因是？
A. 共享资源未被提取到公共依赖包　B. 包体太小　C. 没有使用 LZ4　D. 没有开启 Mipmap

  • 正确答案：A
  • 解析：多个包各自包含同一份共享资源，会导致包体与内存重复；应提取公共依赖或调整分组。

7. Addressables 远程资源更新后，客户端通常需要？
A. 重新安装应用　B. 删除所有缓存　C. 关闭网络　D. 更新远程 Catalog 并重新加载资源

  • 正确答案：D
  • 解析：Catalog 描述资源定位与版本，远程内容更新后需要获取新 Catalog，再按新地址加载。

8. Addressables Group 的 Schema 主要配置什么？
A. 脚本编译选项　B. 字体图集　C. Bundle Mode、内容更新与压缩等打包规则　D. 网络协议

  • 正确答案：C
  • 解析：Group Schema 决定如何打包、是否内容更新、压缩方式等，是资源分组的核心配置。

9. Sprite 被重复打包进多个包，可能是因为？
A. 图集太大　B. 精灵同时被图集包含又被单独引用　C. 没有使用 ASTC　D. 没有 Mipmap

  • 正确答案：B
  • 解析：同一资源被不同引用路径包含时可能重复打包，应统一引用策略并检查构建报告。

10. 纹理开启 Read/Write 的主要影响是？
A. 增加一份 CPU 内存副本　B. 减少内存　C. 自动提升压缩率　D. 只影响音频

  • 正确答案：A
  • 解析：Read/Write 允许 CPU 访问纹理，但会保留额外内存副本，不需要时关闭。

11. ASTC 主要用于？
A. 音频压缩　B. 网络协议　C. 移动端纹理压缩　D. UI 布局

  • 正确答案：C
  • 解析：ASTC 是移动端常用纹理压缩格式，按块大小权衡质量与体积。

12. 短促、高频的 UI 音效最适合的 Load Type 是？
A. Streaming　B. Compressed In Memory　C. 三者一样　D. Decompress On Load

  • 正确答案：D
  • 解析：短音效解压后常驻内存，播放 CPU 开销低；长音乐才用 Streaming。

13. AssetBundle 压缩格式 LZMA 与 LZ4 的典型取舍是？
A. LZMA 包体小但解压慢，LZ4 加载快　B. 完全一样　C. LZ4 包体一定更小　D. LZMA 不能用于移动端

  • 正确答案：A
  • 解析：LZMA 压缩率高但解压慢，LZ4 加载速度快、适合运行时；可按包类型选择。

14. AssetBundle Variant 的典型用途是？
A. 控制脚本编译　B. 为不同分辨率或平台准备不同资源版本　C. 压缩音频　D. 生成字体

  • 正确答案：B
  • 解析：Variant 用于同一逻辑资源的多种版本，例如高清/低清，运行时按设备选择。

15. LoadAssetAsync<T> 与 InstantiateAsync 的主要区别是？
A. 前者只能加载场景　B. 后者只能加载配置　C. 前者加载共享资源，后者创建实例　D. 两者完全一样

  • 正确答案：C
  • 解析：LoadAssetAsync 返回共享资源，修改会影响所有引用；InstantiateAsync 创建独立实例并管理实例生命周期。

16. 在运行时常规流程中使用 WaitForCompletion 的问题是？
A. 一定编译失败　B. 只能用于音频　C. 不释放资源　D. 会阻塞主线程

  • 正确答案：D
  • 解析：WaitForCompletion 同步等待异步操作完成，可能造成明显卡顿，只适合测试或极少数启动场景。

17. Addressables 的引用计数规则是？
A. 每次加载增加，Release 减少　B. 加载不增加　C. Release 会增加　D. 只能手动清空

  • 正确答案：A
  • 解析：加载会增加引用计数，释放会减少；计数归零后才可能真正卸载资源。

18. AssetBundle Manifest 的主要作用是？
A. 存储音频　B. 记录包依赖、哈希等信息　C. 生成 UI　D. 编译 Shader

  • 正确答案：B
  • 解析：Manifest 描述包之间的依赖和资源信息，是加载依赖与版本校验的重要依据。

19. 大量使用 Resources.Load 的主要问题是？
A. 加载太快　B. 自动热更　C. 无法热更且资源常驻包体　D. 不能加载 Prefab

  • 正确答案：C
  • 解析：Resources 目录资源全部打进安装包，无法热更，且容易造成包体膨胀与引用不透明。

20. StreamingAssets 的特点是？
A. 原样打包，可通过路径读取外部文件　B. 自动压缩　C. 自动热更　D. 只能存脚本

  • 正确答案：A
  • 解析：StreamingAssets 不参与 Unity 资源导入流程，适合视频、配置文件等需要按路径访问的文件。

21. 热更新方案中，程序集热更主要解决？
A. 纹理压缩　B. UI 合批　C. 网络同步　D. C# 代码逻辑更新

  • 正确答案：D
  • 解析：资源热更只能更新资源，程序集热更用于更新 C# 逻辑，需要 Lua、ILRuntime 或 HybridCLR 等方案。

22. HybridCLR 的主要特点是？
A. 只能热更资源　B. AOT + 解释器混合，支持 C# 热更　C. 只能用于 Android　D. 不需要构建

  • 正确答案：B
  • 解析：HybridCLR 通过 AOT 与解释器结合补足泛型和动态代码能力，适合纯 C# 团队做热更。

23. link.xml 在 IL2CPP 项目中的作用是？
A. 防止代码裁剪误删反射用到的类型　B. 压缩纹理　C. 配置网络　D. 生成图集

  • 正确答案：A
  • 解析：IL2CPP 会裁剪未直接引用的代码，反射或热更用到的类型需要用 link.xml 保留。

24. Addressables 内容更新后，正确流程通常包括？
A. 只替换本地图片　B. 只清空缓存　C. 重新生成并下载 Catalog，再加载新内容　D. 关闭 CDN

  • 正确答案：C
  • 解析：Catalog 是资源地址与版本索引，内容更新需要同步更新 Catalog，客户端才能定位新包。

25. AssetBundle 加密的主要代价是？
A. 包体自动变小　B. 加载速度自动变快　C. 不需要版本管理　D. 增加加载、调试与兼容成本

  • 正确答案：D
  • 解析：加密增加安全性，但会带来解密开销、调试困难和平台兼容问题，应权衡是否必要。

26. AssetBundle 的 CRC 与版本号主要用于？
A. 生成 UI　B. 校验包完整性与版本匹配　C. 压缩音频　D. 编译脚本

  • 正确答案：B
  • 解析：CRC 可检测包损坏，版本号确保客户端加载正确的资源版本。

27. Addressables 预热（Preload）的主要目的是？
A. 减少首次加载卡顿　B. 增加包体　C. 自动热更　D. 降低内存

  • 正确答案：A
  • 解析：在合适时机提前加载常用资源，可以把卡顿从关键路径前移或摊平。

28. 排查资源泄漏时，Memory Profiler 最关键是看？
A. 显卡型号　B. 屏幕分辨率　C. 引用链　D. 帧率

  • 正确答案：C
  • 解析：快照对比找到新增资源后，需要通过引用链确认谁仍持有它。

29. AssetBundle 构建报告主要用于？
A. 生成 UI　B. 分析包体、依赖与冗余　C. 编译 Shader　D. 播放音频

  • 正确答案：B
  • 解析：构建报告能看出包体大小、资源分布和重复依赖，是分包优化的重要依据。

30. 资源分包的合理原则是？
A. 所有资源打成一个大包　B. 每个文件一个包　C. 只按文件类型分　D. 按模块、生命周期与更新频率划分

  • 正确答案：D
  • 解析：分包要兼顾加载频率、依赖关系、更新范围和包体，不能只按单一维度切分。

二、主观题

1. 设计一个 Addressables 资源加载与释放的封装层。

  • 参考点：统一 Load/Release、引用计数、句柄生命周期、异常与超时、取消令牌、Editor 模拟、缓存策略。

2. 如何定位 AssetBundle 包体冗余？

  • 参考点：构建报告、依赖分析、共享资源提取、图集重复、资源引用路径、包体对比、自动化审计。

3. 热更新资源与代码版本如何保持一致？

  • 参考点：版本清单、Catalog 与程序集版本绑定、CDN 发布、校验、灰度、回滚、客户端兼容旧版本。

4. 如何设计一个可回滚的热更新流程？

  • 参考点：分阶段发布、下载校验、双版本目录、失败回退、启动自检、日志上报、强制更新策略。

5. 资源加载卡顿如何优化？

  • 参考点：异步加载、预加载、拆包、对象池、分帧实例化、减少主线程反序列化、Addressables 预取、真机验证。
