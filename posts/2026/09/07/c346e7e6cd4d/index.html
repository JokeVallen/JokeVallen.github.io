常见问题

委托绑定结构体方法导致装箱

  1. 装箱时机（关键）：装箱发生在 创建委托实例（new） 的那一瞬间，而非调用（Invoke）时。UnityAction<T> 的泛型参数仅保证调用时不装箱，无法干预构造过程。

  2. 根本原因：C# 所有委托的基类（System.Delegate）底层使用 object 类型的字段（_target）来存储方法所属的实例。将栈上的结构体实例赋值给 object 字段时，CLR 强制进行装箱。

  3. 通用规则：这是 C# /.NET 的底层通用机制，与 Unity 引擎无关。无论是 Action、UnityAction 还是自定义委托，行为完全一致。

  4. 唯一规避方案：绑定静态方法（此时 _target 为 null，无装箱），或将数据体改为 class（引用类型）。只要绑定结构体的实例方法，装箱就不可避免。
