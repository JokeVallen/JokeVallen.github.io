Unity编辑器开发案例——代码生成

更新于2026-10-02|Unity开发
|浏览量:

案例视频

前言

在 Unity 项目开发中，我们经常需要根据某些资源批量生成代码或配置，例如：

  • 根据 Excel / TextAsset 生成配置表代码；
  • 根据 ScriptableObject 生成常量类；
  • 根据 Prefab 生成 UI 绑定代码；
  • 根据资源目录生成清单文件。

如果每次手动创建、复制、修改，不仅效率低，而且容易出错。本文实现一个可扩展的 Unity 编辑器代码生成窗口 CodeGenerateWindow，它支持资源拖拽、生成器扫描、批量生成、进度显示、配置持久化等功能。

功能概览

该工具主要包含以下能力：

  • 通过菜单 Game/CodeGenerator 打开生成窗口；
  • 在 Project 窗口右键资源，选择 Assets/Open with CodeGenerate Window，将选中资源加入生成列表；
  • 支持将资源直接拖拽到窗口中；
  • 每个资源可选择输出文件名和对应的生成器；
  • 支持批量生成，并显示整体进度与单项进度；
  • 生成过程中可查看目标资源或生成器的 Inspector 详情；
  • 支持配置输出目录、刷新间隔；
  • 支持重新扫描生成器、清除持久化配置；
  • 使用 EditorPrefs 保存窗口数据，重启 Unity 后仍可恢复。

整体架构

核心脚本如下：

文件 职责
MenuItemExtensions.cs 提供 Project 右键菜单入口
CodeGenerateWindow.cs 代码生成主窗口，管理任务、配置、进度与详情面板
Generator.cs 生成器基类，负责单个/批量生成任务的调度与进度
GeneratorAttribute.cs 标记生成器对应的目标资源类型
FilePathAttribute.cs 指定生成器资产路径，便于持久化生成器配置
GeneratorsCache.cs 扫描并缓存所有生成器实例

整体工作流程如下：

  1. 用户打开 CodeGenerateWindow；
  2. 添加目标资源，每个资源对应一个 Unit；
  3. 为每个 Unit 选择目标类型下可用的 Generator；
  4. 点击 Generate；
  5. 窗口通过 EditorApplication.update 驱动所有 Generator.OnUpdate；
  6. 生成完成后调用 AssetDatabase.Refresh 刷新资源；
  7. 窗口数据通过 EditorPrefs 持久化。

2. 生成器基类

Generator 继承自 ScriptableObject，内部维护待处理队列、活动队列和进度映射：

生成器支持两种模式：

  • 同步模式：重写 OnGenerate，返回 true 表示完成；
  • 协程模式：重写 OnGenerateCoroutine，返回非空 IEnumerator 后，基类会逐帧推进。

同步模式适合小文件生成，协程模式适合耗时较长或需要分帧处理的任务。

使用步骤

  1. 将编辑器相关脚本放入 Editor 文件夹，例如 Assets/Editor/CodeGenerate/；
  2. 创建自定义生成器类，继承 Generator；
  3. 使用 [Generator(typeof(目标类型))] 标记生成器；
  4. 可选：使用 [FilePath("Assets/.../YourGenerator.asset")] 指定生成器资产路径；
  5. 在 Unity 菜单中打开 Game/CodeGenerator；
  6. 将资源拖入窗口，或通过 Project 右键菜单 Assets/Open with CodeGenerate Window 添加；
  7. 为每个资源选择生成器；
  8. 在 Config 页配置输出目录、刷新间隔；
  9. 点击 Generate 开始生成；
  10. 生成完成后查看输出目录中的文件。

注意事项

  • 编辑器脚本建议放在 Editor 文件夹中，避免被打包到运行时；
  • Generator 基类使用了 #if UNITY_EDITOR，如果生成器定义在运行时程序集，需要注意条件编译；
  • 输出路径最好位于 Assets 目录下，否则 AssetDatabase 无法正确导入；
  • 如果使用 [FilePath]，路径必须指向有效的生成器资产，否则会回退为临时实例；
  • 生成器资产修改后，可以点击 Rescan Generators 重新扫描；
  • 大量生成时建议使用协程分帧，避免编辑器卡死；
  • 生成期间工具会锁定程序集重载与自动刷新，生成结束后再统一刷新；
  • Config 中的 Output Directory Path 是窗口级配置，当前代码没有自动注入到 Generator，生成器可以通过自身字段或扩展上下文获取输出目录。

可扩展方向

当前工具已经具备基础框架，后续可以继续扩展：

  • 为 Generator.Context 增加更多用户参数；
  • 支持生成前预览、差异对比；
  • 接入模板引擎，如 T4、Scriban、DotLiquid；
  • 支持依赖收集，资源变更后自动重新生成；
  • 支持生成代码格式化；
  • 支持多选资源批量绑定生成器；
  • 支持生成日志与失败重试。

结语

本文实现了一个基于 Unity 编辑器扩展的代码生成工具。它通过 Generator 基类统一生成流程，通过 GeneratorsCache 自动扫描生成器，通过 CodeGenerateWindow 提供可视化操作界面，并通过 EditorPrefs 持久化配置。整体结构清晰，扩展方便，适合作为项目内代码生成、配置生成、资源绑定等自动化工具的基础框架。
