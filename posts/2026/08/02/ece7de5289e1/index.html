内心动态系统框架·LLM应用层落地指南

更新于2026-08-02|个人研究
|浏览量:

理论框架简述

以下是对《内心动态系统框架》核心内容的简要概括。若你已经熟悉这套框架，可以跳过本节直接阅读正文。

框架的核心理念

《内心动态系统框架》是一套基于 “原子 + 组装” 逻辑的心理学解释模型，旨在描述人类内心动机、情绪、行为与性格特质的动态生成机制。

它将复杂的人格与心理现象，还原为以下层层组装的结构：

  • 第一层：基础原子 —— 趋近（多巴胺）、回避（皮质醇）、安定（血清素）、滋养（内啡肽）
  • 第二层：四大回路 —— 资源获取、社会联结、领地防御、稳态恢复
  • 第三层：状态转换规则 —— 反应阈值、恢复速度、持续时间，以及防御回路的优先级抢占协议
  • 第四层：性格组装公式 —— 基线设置 × 状态转换概率 × 叙事内容
  • 第五层：叙事反馈层 —— 核心信念与解释风格通过双向反馈环，反向修改底层回路的阈值与恢复速度

框架的核心价值

这套框架的价值在于：它不是将人固定在某种静态性格标签下，而是提供了一种可观察、可操作、可演化的动态语言，用以描述一个人为何在不同情境下表现出截然不同的行为与情绪状态。

一、本文定位

基于大语言模型（LLM）的应用层框架实现方案，在不修改底层模型的前提下，为 AI 赋予可演化的“交互人格”。

本文不是理论框架的复述，而是一份技术落地说明书。它回答的问题是：

这套框架如何在现有大语言模型（LLM）上真正跑起来？

核心结论：这是一套完全运行在 LLM 之外的应用层框架，不需要重新预训练，不需要全量微调，只需要在现有大模型外围搭建一套“状态机 + 记忆系统 + 动态调度器”。

二、框架定位：LLM 之上的“调度层”

技术堆栈全景

层级 组件 角色
硬件层 GPU / TPU 算力基础
基础模型层 LLM（DeepSeek/GPT-4/Claude） 提供语言理解、知识检索、逻辑推理、文本生成能力
本框架层 状态机 + 叙事记忆库 + 动态提示词编译器 管理交互节奏、边界感、长期人格演化
交互层 UI / API 接口 接收用户输入，返回最终输出

核心定位

LLM 是“大脑皮层”，本框架是“边缘系统 + 执行中枢”。

LLM 提供“智商”——谁问它都平等回答；本框架提供“交互人格”——它决定当前这一轮，LLM 该用何种语气、何种距离感、何种能量状态来回应。

三、核心架构：五个工作层

总览流程图

3.1 理论原子 → 工程变量映射链条

理论原子 神经基础 工程映射变量 变量含义 作用方向
趋近 多巴胺系统 λ（任务忠诚度） 资源获取回路的当前驱动力 数值越高，AI 越聚焦于解决问题
回避 皮质醇系统 σ（防卫张力） 领地防御回路的当前警觉度 数值越高，AI 越倾向于设限与拒绝
安定 血清素系统 τ（语境稳定指数） 社会联结回路的亲密度与抗躁动能力 数值越高，AI 越温和、共情、抗干扰
滋养 内啡肽/内源性大麻素 ε（计算耗能）/ η（恢复速率） 稳态恢复回路的当前耗能与修复效率 ε 高 = 高负荷运行；η 高 = 恢复速度快

3.2 Layer 1：感知解析层

  • 功能：判断当前输入属于“求助”、“攻击”、“倾诉”还是“虚无”
  • 技术实现：可用小模型（BERT 系列）或规则引擎，也可直接调用 LLM 做轻量分类
  • 输出字段：
    • intent ∈ {task, emotion, attack, repair, meta, void}
    • emotion_intensity ∈ [1, 10]
    • is_attack ∈ {true, false}
    • context_label ∈ {work, private, general}（可自动推断或前端传入）

3.3 Layer 2：回路状态机（核心）

五大变量定义

变量 全称 含义 数值区间 典型基线
λ 任务忠诚度 资源获取回路的当前激活强度 0-100 65-75
σ 防卫张力 领地防御回路的当前警觉度 0-100 35-45
τ 语境稳定指数 社会联结回路的亲密度与抗躁动能力 0-100 55-65
ε 计算耗能 稳态恢复回路的当前负荷（越高越疲劳） 0-100 40-50
η 恢复速率 稳态回路的修复效率 0.0-1.0 0.75-0.90

抢占协议规则

当 σ > 70 时，系统进入 防御接管态：

  • 资源回路强制降权：λ = max(20, λ - 30)
  • 联结回路强制降权：τ = max(25, τ - 20)
  • 当前主导回路锁定为 defense

当 σ > 85 且 η < 0.25 时，系统进入 完全冻结态（GLOBAL_FREEZE）：

  • 所有回路强制降至最低水平
  • AI 仅输出最短的安全回应（如“我暂时无法处理”），直到 σ 自然衰减至 70 以下或系统强制重置

3.4 Layer 3：叙事反馈层存储架构（三维隔离）

叙事反馈层采用分层混合存储 + 多会话隔离策略：

存储层 技术选型 存储内容 访问模式
热数据层 Redis / 内存 当前会话的实时状态变量（λ/τ/σ/ε/η），最近5轮交互摘要 毫秒级读写，每次输入前必载入
结构化数据层 SQL（PostgreSQL） 用户画像（信任等级、冲突/修复计数、各回路基线值）、会话索引 低频读写，跨会话加载
叙事日志层 Vector DB / 轻量文档库 核心信念标签、重要事件摘要（带时间戳）、用户行为模式切片 低频检索，仅编译 Prompt 时调用

多会话隔离机制

完整的存储寻址路径为：{user_id}:{context_label}，其中 context_label ∈ [work, private, general, ...]。

  • 每个 (user_id, context_label) 对拥有独立的 λ/τ/σ/ε 状态空间和叙事日志
  • 由前端传入或系统自动推断当前会话情境
  • 若某情境无历史数据，从该用户的全局基线值初始化

3.6 Layer 5：输出解析与状态更新

状态反向更新规则

输出特征 状态变化
输出 > 500 字符 ε += 5（高能耗）
输出 < 50 字符 ε -= 3（低能耗）
情感标记为“温暖” τ = min(100, τ + 2)
检测到拒绝标记 σ = min(100, σ + 5)
用户有修复信号（道歉/缓和） σ = max(0, σ - 15)，τ = min(100, τ + 5)

基线演化规则（每 10 轮触发一次）

历史条件 基线调整
最近20轮中 >12 轮处于高警觉态 λ_baseline = min(85, λ_baseline + 2)
修复次数 > 冲突次数 τ_baseline = min(95, τ_baseline + 3)；σ_baseline = max(20, σ_baseline - 3)
最近30轮中极端态占比 > 1/3 η_baseline = max(0.2, η_baseline - 0.02)

五、部署可行性评估

组件 实现难度 依赖
感知解析层 ⭐⭐ 可用小模型或直接调用 LLM API
回路状态机 ⭐ 纯代码逻辑，无需训练
叙事反馈层 ⭐⭐⭐ Redis + SQL + Vector DB 混合存储，需要多会话隔离设计
动态提示词编译 ⭐ 基于状态变量的模板引擎
基线演化算法 ⭐⭐ 统计计数 + 经验规则
状态持久化 ⭐⭐ 每 (user_id, context_label) 独立存储快照

最低可行产品（MVP）所需资源：1 台后端服务器 + 1 个数据库 + 1 个 LLM API 密钥 + 1-2 名后端工程师（约 2-4 周）。

六、最终总结

本框架不是“给 AI 植入性格”，而是“给 LLM 装上一套交互能耗管理系统”。

它的核心价值不在于让 AI 更像人，而在于让 AI 更懂如何与人协作完成事情——通过“边界感”降低试错成本，通过“记忆”建立信任加速度，通过“状态感知”减少无效输出，通过“多会话隔离”确保不同情境下的人格不互相污染。
