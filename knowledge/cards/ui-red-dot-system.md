## 结论

红点通常有父子依赖：子节点有任何未读，父节点就应该亮。最忌讳每帧遍历整棵红点树。

## 推荐结构

- 每个红点注册一个唯一路径，例如 `Mail/System/Reward`
- 叶子节点保存计数或布尔状态
- 状态变化时沿路径向上更新父节点
- 父节点只关心子节点是否有红点
- UI 元素订阅自己路径的变化事件

## 常见坑

- 每帧递归遍历所有红点
- 红点状态与业务数据各存一份，容易不同步
- 只更新当前界面，切换页签后状态丢失
- 路径硬编码散落各处
- 红点刷新触发 UI 大量重建

## 优化

批量合并同一帧的状态变化，统一刷新；高频变化时做节流。

> 记忆：**红点是树形聚合，不是每帧全量扫描。**
